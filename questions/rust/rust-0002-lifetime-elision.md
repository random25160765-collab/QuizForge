阅读下面两段代码。

**代码 A**（可以编译）：

```rust
fn first_word(s: &str) -> &str {
    s.split_whitespace().next().unwrap_or("")
}
```

**代码 B**（无法编译）：

```rust
fn longest(a: &str, b: &str) -> &str {
    if a.len() >= b.len() { a } else { b }
}
```

请回答：

1. 代码 B 报错的原因是什么？编译器的错误信息会给出什么建议？
2. 为什么代码 A 不需要写生命周期标注就能通过？请写出**生命周期省略规则**，
   并说明代码 A 依赖的是哪几条。

## 参考答案
**1. 代码 B 报错的原因。**

函数有**两个输入引用参数、一个输出引用参数**，编译器无法确定返回的引用
是从 `a` 借来的还是从 `b` 借来的。省略规则在这种情况下不适用，
于是返回类型被推导为「某个匿名生命周期」，但它与哪个输入关联是未知的，
因此报错（E0106：missing lifetime specifier）。

即使写成语义上「运行时只有一支会返回」，编译器也不会做这种路径分析——
生命周期是**类型系统层面**的信息，必须对所有控制流统一成立。

编译器的建议是显式标注，并且用 `'a` 把两个输入与输出绑在一起：

```rust
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}
```

要注意这个签名有**实际后果**：它把两个输入的生命周期合并成同一个 `'a`，
因此返回值的存活期受**较短的那个输入**限制。调用方如果传入一个长生命周期
和一个短生命周期的字符串，在短的那个失效之后就不能再使用返回值了。
这就是「生命周期标注不是用来『让它编译过』，而是用来**向调用方承诺返回值的有效范围**」。

**2. 生命周期省略规则与代码 A。**

Rust 的生命周期省略（elision）有三条规则，按顺序应用：

* **规则 1（输入侧）**：每个被省略的输入位置的生命周期，各自成为一个**独立的**生命周期参数。
  例如 `fn f(a: &str, b: &str)` 展开为 `fn f<'a, 'b>(a: &'a str, b: &'b str)`。
* **规则 2（输出侧，单输入）**：如果**恰好只有一个**输入生命周期（无论是否省略），
  那么所有被省略的输出生命周期都等于它。
* **规则 3（输出侧，方法）**：如果参数中有 `&self` 或 `&mut self`，
  那么所有被省略的输出生命周期都等于 `self` 的生命周期。

代码 A 命中的是**规则 1 + 规则 2**：

```rust
fn first_word(s: &str) -> &str
// 规则 1：s 展开为 &'a str
// 规则 2：只有一个输入生命周期 'a，输出的 &str 也就等于 &'a str
```

所以它等价于：

```rust
fn first_word<'a>(s: &'a str) -> &'a str
```

这也是一个重要的**接口约定**：`first_word` 返回的切片指向 `s` 内部，
因此它的存活期不能超过 `s`。

相比之下代码 B 有两个输入生命周期，规则 2 因「不唯一」而无法应用，
规则 3 也不适用（没有 `self`），于是必须由程序员显式标注。

**补充**：省略规则只作用于 `fn` 签名，不作用于结构体字段或 `impl` 块。
Rust 2018 之后 `'_` 可以显式表示「这里省略，请按规则推导」，
例如 `struct Parser<'a> { input: &'a str }` 必须写出 `'a`，
但 `impl<'a> Parser<'a> { fn input(&self) -> &'_ str { self.input } }` 中的 `'_`
就交给规则 3 处理。

## 评分要点
- 说明代码 B 报错是因为有两个输入引用、无法确定返回值借用自哪一个（E0106）
- 给出显式标注写法 `fn longest<'a>(a: &'a str, b: &'a str) -> &'a str`
- 指出标注的语义后果：返回值受较短的那个输入约束，而不是「随便加个 'a 让它通过」
- 至少正确写出省略规则 1（每个输入参数各自独立）与规则 2（单输入时输出沿用输入）
- 明确代码 A 命中规则 1+2，并展开成 `fn first_word<'a>(s: &'a str) -> &'a str`
- 提到规则 3（&self / &mut self 时输出等于 self）
- 可选加分：提到省略规则只适用于 fn 签名、`'_` 的用法，或返回值指向输入内部这一接口承诺
