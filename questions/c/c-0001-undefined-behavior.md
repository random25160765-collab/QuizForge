下面这段代码在 `-O2` 下编译运行，`x` 的输出值是什么？

```c
int x = 1;
int *a = &x;
float *b = (float *)a;
*b = 2.0f;
printf("%d\n", x);
```

## 选项
- A. 一定输出 `2`：因为 `b` 指向的就是 `x` 的存储位置，写入后 `x` 的值自然是浮点位模式对应的整数
- B. 一定输出 `1`：因为 `x` 声明为 `int`，编译器据此认为 `x` 不会被通过 `float*` 修改，于是把 `printf` 里的 `x` 直接常量折叠为 `1`
- C. 行为是未定义的（违反严格别名规则），编译器可以做任意假设；实测常见结果是 `1`（常量折叠），也可能输出 `2` 或别的值，取决于优化级别与目标平台
- D. 保底输出 `2`：C 标准要求通过不同类型指针写入后，读取原类型的对象必须看到新值，这属于 `memcpy` 语义的保证

## 答案
C

## 解析
这道题的关键词是 **严格别名（strict aliasing）**，规则写在 C11 §6.5 第 7 段：
一个对象的存储只能通过**兼容类型**、**带符号/无符号对应版本**、
**`char` / `unsigned char` / `signed char`**、或**包含上述类型的聚合体/联合体**来访问。

`int` 与 `float` 既不是兼容类型，也不是彼此的符号对应版本，因此
`*(float *)&x` 违反规则，行为未定义。

**为什么实测常常输出 `1`。** 既然行为未定义，编译器就有权假设
「`int` 对象不会被 `float*` 修改」。于是 `x` 在 `printf` 处可以被当作常量 `1`
直接折叠进立即数——**它甚至不需要从内存里读一次**。这就是
「代码里明明写了赋值，输出却是旧值」的来源。

也可能出现其它结果：

* 某些平台上 `-O0` 不做别名分析，于是老老实实从栈上读，输出
  `x` 的位模式被 `2.0f`（`0x40000000`）覆写后的整数 `1073741824`；
* 有些 ABI 会把 `x` 放在寄存器里，压根不存在「被覆写」这件事。

**逐项辨析：**

* **A 错。** 把「b 指向同一块存储」当成保证，忽略了类型信息对优化的影响。
* **B 错。** 「一定」太强。结果依赖编译器、优化级别与目标平台，
  标准层面只能是「未定义」。
* **C 对。** 正确描述了未定义行为的性质，也点出了常见实测结果。
* **D 错。** `memcpy` 的字节级复制语义是 `memcpy` 接口自身的保证，
  而不是「任意类型指针互转」的保证。用 `memcpy` 可以合法地做类型双关
  （type punning），用指针解引用则要遵守别名规则。

**正确的替代写法：**

```c
#include <string.h>

/* 1) 用 memcpy 做合法的类型双关 */
float f = 2.0f;
memcpy(&x, &f, sizeof x);

/* 2) 目标就是「按位重解释」时，用联合体（C99 起明确允许） */
union { int i; float f; } u;
u.f = 2.0f;
printf("%d\n", u.i);

/* 3) 确实需要绕过别名假设时，用 -fno-strict-aliasing 编译整个单元 */
```

在写底层代码（内存池、序列化、SIMD 内核、内核模块）时，
「通过 `char *` 逐字节访问」是合法的；一旦换成 `int *` / `float *` / 结构体指针
去访问一块本就属于别的类型的存储，就要停下来问一句：这是不是未定义行为。
