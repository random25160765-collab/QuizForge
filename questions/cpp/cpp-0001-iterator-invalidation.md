下面的代码对 `std::vector<int> v` 调用 `reserve`，然后继续使用此前保存的迭代器。
哪一句描述是正确的？

```cpp
std::vector<int> v{1, 2, 3};
auto it = v.begin();

v.reserve(100);      // (1)
v.push_back(4);      // (2)

std::cout << *it;    // (3)
```

## 选项
- A. `(1)` 与 `(2)` 都不会使 `it` 失效，`(3)` 一定输出 `1`
- B. `(1)` 不会使 `it` 失效，但 `(2)` 之后的 `it` 仍然指向原元素，`(3)` 一定输出 `1`
- C. `(1)` 已经使 `it` 失效；由于 `reserve` 之后容量足够，`(2)` 不会再搬运元素，但 `(3)` 仍然是未定义行为
- D. `(1)` 不会使 `it` 失效，`(2)` 也不会，标准保证 `reserve` 之后的迭代器长期有效

## 答案
C

## 解析
这里要区分两件事：**「元素没有被搬移」和「迭代器仍然有效」不是一回事**。

`reserve(100)` 会重新分配一块容量为 100 的缓冲区。如果 `100 > v.capacity()`，它就是一次
真实的重新分配：新缓冲区、搬移元素、释放旧缓冲区。按 C++ 标准
（`[vector.capacity]` / `[vector.modifiers]`），**任何导致容量变化的操作都会使全部迭代器失效**，
无论 `reserve` 是否真的触发了分配——标准不要求实现区分这两种情况。

`(2)` 的 `push_back` 因为容量已有 100，不会再分配，因此「元素地址不变」，
但标准给出的失效规则同样是「若未发生重新分配，只有被插入位置之后的迭代器失效」，
而 `it` 指向第一个元素，严格来说在 `(2)` 之后仍指向原元素。

真正的问题在于 `(1)`：`it` 在 `reserve` 之后**已经失效**。此后解引用 `it` 属于
**未定义行为**，即使本次运行时恰好打印出 `1`，也不能依赖。

因此正确做法是 `reserve` 之后重新取 `v.begin()`：

```cpp
v.reserve(100);
auto it = v.begin();   // 在可能改变容量的操作之后重新获取
```

常见的记忆锚点（对 `vector`）：

| 操作 | 迭代器失效范围 |
|---|---|
| `reserve` / 触发扩容的 `push_back` | 全部失效 |
| 未触发扩容的 `push_back` / `emplace_back` | 只有 `end()` 失效（即此前保存的 `end()` 不可用） |
| `insert` / `erase` | 插入点或删除点及其之后失效 |

注意最后一行：`push_back` 不扩容时，**此前保存的 `end()` 迭代器仍然失效**，
因为它不再代表末尾——这是比「指针是否被搬移」更准确的心智模型。
