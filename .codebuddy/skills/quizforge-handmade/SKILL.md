# 人工手写的单题：接进来，别让它成孤岛

**agent 的角色是「接」，不是「出」。** 题面由人给，agent 负责把它变得**与框架兼容**：
`check.py` 能过、前端能渲染判分、字段能被解析成知识图谱的边。

一句话理由：手写题如果没接上关系边，它在图谱外面——既不被学习算法调度，也不参与覆盖统计。

## 一、先看清人给的是什么

| 人给的形态 | 处理方式 |
|---|---|
| 已经是契约格式的 `.md` | 只补元数据 + 校验（最省事） |
| 自由文本（题干 + 答案 + 零散说明） | **结构化转写**：映射到固定小节，**题面一个字不改** |
| 只有题面与答案，没有解析 / 评分要点 | 补写，并在报告里**明确标注「由 agent 补写，请复核」** |

## 二、必须注入的上下文（兼容性清单）

### 1. front-matter

```yaml
id: <学科>-<四位编号>          # 全局唯一，kebab-case，以目录名开头
type: problem                  # single | multi | blank | short | problem
topic: <meta/topics.yaml 里的 key>
layer: 迁移                    # 识记 | 理解 | 应用 | 迁移 —— 学习算法的坐标轴，别留空
wing: 创新                     # 基础 | 综合 | 应用 | 创新
difficulty: 5                  # 1..5，次要字段，只作粗粒度参考
chapter: <章节名>
source: "<材料文件>: <小节标题>"   # 人类可读线索，不做机器核对；填到小节级
```

### 2. 正文小节：名字固定，不许自创

只允许：`提示` / `选项` / `答案` / `参考答案` / `评分要点` / `小问` / `解析`。
自创小节名会被 `check.py` 判 ERROR。**第一个小节之前的正文就是题面。**

法式大题（`type: problem`）的骨架——`### 小问标题` **必须**写在 `## 小问` 之后：

```markdown
**题干** <公共题面：背景、符号定义、参数表、约束条件>

**说明** 本大题共 N 问，分 K 部分。每一问的结论会被后续小问复用，建议按顺序作答。

## 小问

### 第一部分 · 第 1 问｜<小问标题>
<该问的要求>

#### 提示
可选，作答前可见。

#### 参考答案
<完整解答，可含公式与代码>

#### 评分要点
- <可判定命中的短句>

### 第一部分 · 第 2 问｜……
```

其它题型：`single`/`multi` 用 `## 选项` + `## 答案`（选项行 `- A. xxx`，答案 `B` 或 `A,C`）；
`blank` 的 `## 答案` **每行一个空**，同一空的多个可接受写法用 `|` 分隔、以 `~` 开头的整段按正则；
`short` 必须有 `## 参考答案`，建议有 `## 评分要点`。细节一律看 `references/format.md`。

### 3. 让关系边能被解析出来（这一节是「不成孤岛」的关键）

图谱的边**不是标出来的，是从固定句式里解析出来的**（见 `references/pipeline.md` §4）。手写时把这几句写上：

| 边 | 写在哪 / 怎么写 |
|---|---|
| **前置边** | 小问里写「可引用第 N 问的结果」；或题面写「每一问的结论会被后续小问复用」 |
| **易混边** | `single`/`multi` 的 `## 解析` 里写 `### 选项辨析`，逐条写「**B 错**：<错在哪 + 什么人会选它>」 |
| **迁移边** | `layer: 迁移` 的题，`## 解析` 开头一句：「本题把 <原理> 迁移到 <新情境>，相对于 <原知识点> 的变式是 <换情境 / 换问法 / 跨点综合>」 |
| **锚定边** | `source` 填到**小节级**，别只写文件名 |

### 4. 图片

- 默认**重绘**：让多模态模型读图后产出 SVG / mermaid / graphviz，**不拷原图**（公开仓库里拷第三方图等于二次分发）
- 必须用原图时放 `assets/figures/<材料>/`，用 `![说明](相对路径)` 引用，**alt 必须写全**
- **结构图不要用文生图模型画**——「谁连谁、箭头朝哪」正是考点，文生图会画错

### 5. 其它硬规则

- 行内公式 `$...$` **必须同行闭合**，跨行不渲染 → 改块级 `$$...$$`
- 代码块标语言：`c` `cpp` `cuda` `ptx` `rust` `python` `bash` `asm` `json` `yaml` `toml` `text`
- 大题的**问数不设上限**：长链条是正常的，按内容需要写；但每问要能独立判分

## 三、agent 不做的事

- **不改题面内容** —— 人写的题面就是事实，只有格式问题才动（小节名、公式跨行这类）
- **不顺手改难度、不删小问** —— 觉得有问题就**提出来**，由人决定
- **不因为「看起来像另一层」就改 `layer`** —— 提出来，由人定
- 不为了「看起来完整」而补出一道新题 ✗

## 四、跑完这些才算接上

```bash
cd /home/rd/Desktop/quizforge
python3 tools/check.py questions/<学科>/<file>.md   # 单题：必须 0 error
make check                                          # 全库基线不能变红
make test                                           # 前端逻辑自测：渲染与判分都过一遍

# 入库（在线版，先看影响面、不写库）
cd api && .venv/bin/python -m app.cli.import_bank --dry-run
```

## 五、交付报告（固定五项）

1. `check.py` 的**原始输出**（不要只写"通过"）
2. **哪些字段是 agent 补的**（尤其解析与评分要点），逐项列出请人复核
3. 从这道题**能解析出哪些关系边**（前置 / 易混 / 迁移 / 锚定）——这是它进图谱的凭证
4. agent 认为需要人拍板的地方（层级归属、难度、图片处理方式）
5. 入库影响面（`--dry-run` 的输出）
