# quizforge 题目格式契约

## 目的

保证任何一次产出的题目文件都**与 quizforge 框架的解析契约完全兼容**：
`tools/check.py` 零错误、`tools/build.py` 能正常构建、前端能正确渲染与判分。

## 与层契约的分工

出题**不要**用本 skill，用对应层次的那份契约 —— 它们在 `pipeline/prompts/layers/`
（那是**出题机的内部提示词**，被 `pipeline/worker.py` 读进出题员的提示词，
所以不放在 `.codebuddy/skills/` 里）：

| 要出什么 | 哪份契约 |
|---|---|
| 识记层（术语、定义、数值、枚举的准确回忆） | `pipeline/prompts/layers/l1-memorize.md` |
| 理解层（预测、判断、解释机制） | `pipeline/prompts/layers/l2-understand.md` |
| 应用层（按规程算出确定结果） | `pipeline/prompts/layers/l3-apply.md` |
| 迁移层（换情境、换问法、跨点综合） | `pipeline/prompts/layers/l4-transfer.md` |

本 skill 只负责**格式契约**：字段怎么填、正文小节怎么写、写完跑什么命令。
层契约负责**这一层怎么出题、怎么判断有没有滑坡**，并指向 `references/format.md` 取细节。

**四层共用同一条流水线，不分批。** 任务按**知识点**打包，一次把该出的都出了；
一个点出哪几层由它自己的 `layers` 决定（含识记/理解就出 `single`/`multi`/`blank`，
含应用/迁移就出 `problem`/`short`）。**层是内容维度**（题怎么写、怎么判定），
**不是流程维度**——不存在「先出一批 L1/L2、再单独出一批 L3/L4」这种分批。

四个阶段固定：**派工（按点打包）→ 出题 → 独立校验（不合格带缺陷清单重出）→ 统合入库**。

**不要预定「L1 几道、L2 几道」的比例**：题量是材料的函数（覆盖率下限），不是预算；
L1/L2 占大头是**结果**而不是计划。理由是推理已被外包给 agent，瓶颈变成「能不能读懂 agent 的输出」，
而读懂靠词汇量与基本理解；独立完成高层级推理仍是高级工程师的要求，要有，但频率低、每题吃得深。
批量流程（切片分档、覆盖矩阵、任务打包、独立校验、并行分工）见 `references/pipeline.md`。
这套重排的完整论证见 `docs/THESIS.md`（业务立论——本仓库所有取舍的根据）。

**受众不作为设计维度**：四层已经覆盖了受众差异——考试 / 面试 / 教学的区别是「考到哪一层、要多细」，
不是另一套题。场景差异只落在两处：**使用方式**（闭卷限时 vs 开卷审读）与
**`## 解析` / `## 评分要点` 的写法**。解析写得实，同一道题就能当教案、当面试评分表。

## 项目位置

仓库根目录：**就是这个仓库的根** —— 下文所有路径都相对它。
克隆到哪台机器、哪个目录都行；skill 里不写死绝对路径
（要拿根目录：`git rev-parse --show-toplevel`）。

```
quizforge/
├── meta/topics.yaml          # 考纲主题树（topic 的唯一事实来源）
├── questions/<topic>/        # 题库：一个 .md 一道题
├── tools/                    # vendor.py / check.py / build.py / new_question.py / question_parser.py
├── api/web/                  # 前端构建产物（不要手改：改 theme/ 后 make web）
└── .codebuddy/skills/        # 本批 skill 的实体（仓库自包含）
```

本批 skill 的**实体就在仓库里**，跟着仓库走：整份拷走、归档、换机器打开都不会断链。
若某个工作区根不在本仓库内（例如工作区根是仓库的上一级），
在仓库根跑一次 `make skills-link` 把指针建过去即可 —— 那只是指针，实体仍只有一份。

## 核心约束（先读这条）

**出题依据的优先级：原材料内容 + 用户诉求 > 考纲。**
`meta/topics.yaml` 只用于**归类**，而且它是随时可以重构的。材料值不值得出、该出什么，
只看材料本身写清了什么、以及用户要什么。不要为了填满某个知识点而出题，
也不要因为考纲里没有合适的 key 就不出题 —— 正确顺序是「先出题 → 最后归类 → 兜不住就改考纲」。

1. **一道题一个 `.md` 文件**，放在 `questions/<topic>/` 下，文件名 `<topic>-<四位编号>-<英文短横线描述>.md`。
2. **`topic` 必须是 `meta/topics.yaml` 里已定义的 key**。需要新主题时先改 `meta/topics.yaml`（加 key/name/group/order/color/desc），再建目录。
3. **`id` 全局唯一**，kebab-case，且以目录名（即 topic）开头。
4. **正文小节必须用 `##` 二级标题，且名称固定**：`提示` / `选项` / `答案` / `参考答案` / `评分要点` / `小问` / `解析`。
   不要自创小节名（解析器会直接报错）。
5. **LaTeX 行内公式必须在同一行内闭合**。跨行的 `$...$` 不会被渲染，请改成块级 `$$...$$`。
6. 新增或改完题目后，**必须**依次运行：

```bash
cd "$(git rev-parse --show-toplevel)"  # 仓库根（克隆在哪都行）
python3 tools/check.py          # 必须先到 0 error
python3 tools/build.py          # 构建成功即表示前端能解析
```

只有 `check.py` 报 `[OK] ... 全部通过` 才算完成。若有告警（WARN），逐条判断是否需要修。

## 工作流

1. **确认 topic**：读 `meta/topics.yaml`，选定已有 key；没有合适主题就先加。
2. **选题型**：single（单选）/ multi（多选）/ blank（填空）/ short（简答）/ problem（大题）。
   优先用 `short` 还是 `problem`？见下方「题型选择」。
3. **生成骨架**（推荐，避免手写字段出错）：

```bash
python3 tools/new_question.py --topic cpp --type single --title 迭代器失效 --chapter "STL 容器"
```

   会打印新建文件的相对路径。`problem` 与代码填空需要手工补 front-matter，见参考文档。
4. **写内容**：严格按 `references/format.md` 里对应题型的模板。所有 LaTeX 用 `$...$` / `$$...$$`。
5. **校验 + 构建**，按需修正直到 `check.py` 通过。
6. 向用户汇报：新增/修改了哪些文件、`check.py` 的最终输出、构建后的题量变化。

## 题型选择

| 场景 | 题型 |
|---|---|
| 有明确唯一正确选项的辨析题 | `single` |
| 需要多选、且漏选应有部分分 | `multi` |
| 答案是一个词/数字/短表达式/一串代码 | `blank` |
| 开放作答、用一段话讲清楚 | `short` |
| **多个小问层层递进**（法式大题、综合题、n 问推导） | `problem` |

**判断标准**：如果题目里有「第 1 问 / 第 2 问 …」这种编号小问，或者小问的结论会被后续小问复用，
就必须用 `problem`，不要硬塞进一个 `short` 的文本框。

## 参考文档（按需读取，不要一次全读）

- `references/format.md` —— **必读**。字段速查表 + 五种题型的完整模板（含代码填空 `blankMode: code`、
  大题 `## 小问` + `#### 参考答案` / `#### 评分要点` 的精确写法）。
- `references/from-source.md` —— 从现有资料（书稿、仓库、笔记）出题的工作流与注意事项（**单批**：几道题）。
- `references/pipeline.md` —— **批量**流程（一本书 / 一套手册 / 几百篇论文）：批次分三类、
  切片分档与四条纪律、覆盖矩阵与任务打包、存储约定、关系靠解析而非标注、
  为什么不用向量库与图数据库、并行/串行的分工与成本估算。

## 反例（常见错误）

- ❌ 用 `### 第 1 问` 却不加 `## 小问` 小节 → 解析器报「「## 小问」小节里必须先写 `### <小问标题>`」。
- ❌ 把答案写进 front-matter 的 YAML → 不支持，答案必须放在 `## 答案` 小节。
- ❌ 填空题用 `|` 分隔多个可接受答案时，把正则也塞进同一段并用 `|` 连接 →
  正则必须整段放在 `~` 之后直到行尾（正则内部可自由用 `|`）。
- ❌ 单选/多选的答案字母不在 `## 选项` 里 → `check.py` 直接报 ERROR。
- ❌ 手改 `api/web/` 下的产物 → 那是构建产物，改 `theme/` 后重新 `make web`。
