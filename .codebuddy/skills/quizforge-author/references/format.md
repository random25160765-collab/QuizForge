# quizforge 题目格式契约

## 1. 文件位置与命名

```
quizforge/questions/<topic>/<topic>-<四位编号>-<英文短横线描述>.md
```

例：`questions/cpp/cpp-0004-smart-pointer-cycle.md`

- 目录名 = `topic`，必须是 `meta/topics.yaml` 里已定义的 key。
- 编号从 `0001` 起，同 topic 内不重复（`tools/new_question.py` 会自动分配）。
- 以 `_` 开头的文件（如 `_TEMPLATE.md`）会被构建忽略，可放草稿。

## 2. front-matter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 全局唯一，kebab-case，建议以 topic 开头 |
| `type` | ✅ | `single` / `multi` / `blank` / `short` / `problem` |
| `topic` | ✅ | 必须是 `meta/topics.yaml` 的 key |
| `layer` | ✅ | 掌握层次：`识记` / `理解` / `应用` / `迁移` —— 这道题在考哪种认知操作 |
| `wing` | ✅ | 训练类型：`基础` / `综合` / `应用` / `创新` —— 这道题属于哪种训练形式 |
| `chapter` | 建议 | 章节名，用于分组与统计 |
| `tags` | 建议 | 列表，用于筛选与组卷 |
| `difficulty` | 可选 | 1–5，默认 3。**次要字段**，只作粗粒度参考 |
| `source` | 可选 | 出处（材料文件 + 小节标题）。人类可读线索，**不做机器核对** |
| `caseSensitive` | 可选 | `true` 时填空答案区分大小写（默认区分） |
| `blankMode` | 可选 | `inline`（默认，单行输入）/ `code`（多行等宽输入） |
| `blankLines` | 可选 | `blankMode: code` 时的输入框行数，默认 6 |

### `layer` 与 `wing`

这两个字段描述的是**这道题在考什么**。它们**不出现在界面上**，但必须落盘：

出题时判断「某个知识点已经覆盖了哪几层、哪几翼」只能靠它们。
不落盘的话，每次开新 session 都只能靠猜，结果是反复出同一层的题、
某一翼长期为空——而「同一知识点能分别出四层」恰恰只能靠覆盖情况来保证。

| `layer` | 认知操作 | 常用题型 | 默认 `wing` |
|---|---|---|---|
| `识记` | 准确回忆、而且不混淆 | single / multi / blank | `基础` |
| `理解` | 预测、判断、解释机制 | single / multi / short | `基础` |
| `应用` | 按已知规程独立算出确定结果 | blank / problem | `应用` |
| `迁移` | 换情境、换问法、跨知识点综合 | problem / short | `创新` |

四种层次各自怎么构造题目、怎么判断有没有滑坡，见对应的层 skill：

- `quizforge-l1-memorize`（识记）
- `quizforge-l2-understand`（理解）
- `quizforge-l3-apply`（应用）
- `quizforge-l4-transfer`（迁移）

`difficulty` 与 `layer` 不冲突但不同维度：`layer` 是「考哪种认知操作」（可枚举、可校验），
`difficulty` 只是同一层内部的难易参考。选题与复习计划以 `layer` / `wing` 为准。

## 3. 正文小节契约

只允许这些 `##` 小节名：`选项` `答案` `参考答案` `评分要点` `提示` `小问` `解析`

规则：

- 第一个小节之前的正文 = 题面（Markdown + LaTeX + 代码块）。
- `##` 标题必须顶格（最多 3 个空格缩进）；代码围栏内的 `##` **不会**被当作小节。
- `## 答案` 的写法按题型不同（见下）。
- `single` / `multi` 必须同时有 `## 选项` 与 `## 答案`。
- `short` 不需要 `## 答案`，必须有 `## 参考答案`（缺失是 ERROR），建议有 `## 评分要点`。
- `problem` 必须用 `## 小问`，不用 `## 答案`。

## 4. 题型模板

### 4.1 single（单选）

```markdown
---
id: cpp-0004
type: single
topic: cpp
chapter: STL 容器
tags: [STL, 迭代器]
difficulty: 2
---

题干，可以混排行内公式 $O(n\log n)$ 与代码块：

```cpp
std::vector<int> v;
```

## 选项
- A. 第一个选项
- B. 第二个选项
- C. 第三个选项

## 答案
B

## 解析
解析正文，支持 Markdown、公式与代码块。
```

- 选项行支持 `- A. xxx` / `- A、xxx` / `- A) xxx`，也可以省略字母（自动按 A、B、C 编号）。
- 答案只能有 1 个字母，且必须出现在选项里。

### 4.2 multi（多选）

与 single 相同，差异在答案：用逗号分隔，**至少 2 个**。

```markdown
## 选项
- A. 选项一
- B. 选项二
- C. 选项三

## 答案
A,C
```

判分：全对 = correct；只选中部分正确项 = partial（按比例给分）；选到任何错误项 = wrong。

### 4.3 blank（填空，单行输入）

`## 答案` **每行对应一个空**；同一空的多个可接受答案用 `|` 分隔。

```markdown
## 答案
1000|1e3
O(n)
```

上面表示 2 个空：第 1 空接受 `1000` 或 `1e3`，第 2 空接受 `O(n)`。

**正则的写法**：`~` 之后**直到行尾**整体是一条正则，`~` 之前的才是用 `|` 分隔的字面答案。
正则内部可以自由使用 `|`，不会与分隔符冲突。

```markdown
## 答案
有效但未指定|~^有效.{0,8}(状态|值)
```

- 比较前会做归一化：去首尾空白、折叠连续空白、剥掉包裹的引号（`` ` `` `"` `'` `“”` `‘’` `《》`）、去掉结尾的 `；;。，,`。
- 默认**区分大小写**；需要忽略大小写时在 front-matter 加 `caseSensitive: false`。

### 4.4 blank + 代码填空（多行输入）

需要在 front-matter 声明 `blankMode: code`。渲染为等宽多行文本框，回车换行、`⌘/Ctrl+Enter` 提交。

```markdown
---
id: cpp-0005
type: blank
topic: cpp
blankMode: code
blankLines: 8
caseSensitive: false
---

补全下面函数：

```cpp
Buffer(Buffer&& other) ____________________ : data_(other.data_), size_(other.size_) {
    other.data_ = nullptr;
    other.size_ = 0;
}
```

**第 1 空**：初始化列表前需要补什么关键字？

## 答案
noexcept
```

要点：

- 归一化会把换行折叠成空格，因此**多行答案与单行答案按同一套规则比较**。
- 需要「任意写法都算对」时用 `~` 正则，例如 `~noexcept(\s*\(.*\))?`。

### 4.5 short（简答）

```markdown
---
id: rust-0003
type: short
topic: rust
chapter: 所有权
---

题干。可以分几段提出多个子问题，但仍属于同一问。

## 参考答案
完整参考答案，可含公式与代码。

## 评分要点
- 要点一
- 要点二
- 要点三
```

- **`## 参考答案` 缺失是 ERROR**，`## 评分要点` 缺失是 WARN。
- `## 评分要点` 每行一条（`-` / `*` / `1.` 前缀都会被剥掉），会作为 rubric 传给 AI 批改。
- 要点要写成**可判定是否命中**的短句，不要写成「回答得好」这类无法判断的表述。

### 4.6 problem（大题 / 法式大题）

适合「多小问层层递进」的综合题。结构：

```markdown
---
id: cuda-0004
type: problem
topic: cuda
chapter: GEMM 优化
difficulty: 5
---

**题干** 公共题面：背景、符号定义、硬件参数、约束条件。

**说明** 本大题共 N 问，分 K 部分。

| 参数 | 数值 |
|---|---|
| 峰值算力 | $312$ TFLOPS |

## 小问

### 第一部分 · 第 1 问｜小问标题
1. 第一小问的具体要求。
2. 第二小问的具体要求。

#### 提示
可选。作答前可见的提示，默认折叠。

#### 参考答案
这一问的完整解答，支持公式与代码块。

$$
\text{读取次数} = 2MNK
$$

#### 评分要点
- 要点一
- 要点二

### 第一部分 · 第 2 问｜下一个小问
……
```

关键规则：

- `### <小问标题>` 划分小问，**必须**写在 `## 小问` 之后。
- 小问内部的 `#### 参考答案` / `#### 评分要点` / `#### 提示` 三个四级标题是可选分块标记，
  名称必须以 `参考` / `评分` / `提示` 开头。
- 每个小问的题干不能为空（ERROR）。
- 未写 `#### 评分要点` 或 `#### 参考答案` 只是 WARN，但**强烈建议都写**，
  否则 AI 批改缺少 rubric、学习者看不到解答。
- 小问编号按出现顺序自动生成（第 1 问、第 2 问 …），无需手写编号。
  标题里写「第 N 问」只是给人看的。
- 大题在 UI 上表现为：公共题面 → 小问导航（已答/未批改状态）→ 每问独立文本框 +
  独立 AI 批改 + 可折叠的解答与评分要点。

**出题建议**：大题的每一问应能独立判分；把「需要复用前问结论」写进题干，
不要写成互相依赖到无法单独作答。**小问数量不设上限**：有的知识本身就是一条长链条
（环节多、演化历史长），从朴素实现一路推到工业级参数，几十问是正常的 —— 按内容需要
该写多少问就写多少问，不要为了控制篇幅去砍问题（一砍就容易把分支点砍掉，而分支点
正是这类题的价值所在）。
题长不妨碍使用：UI 上大题是逐问导航、每问独立作答与批改，不需要一次做完。

**大题的组织原则**（决定它是一张「学习地图」还是一份「长练习」）：

- **问序不可交换**：每一问都必须是上一问解决之后**暴露出来的下一个问题**。
  判据是——把顺序打乱，如果仍然成立，说明它只是把几个知识点拼在一张卷子上，
  有考试功能、没有指引功能，应当重排或拆成小题。
- **必须带分支点**：至少有几问要问「条件改变时该往哪拐」（例如「如果 L2 够大，这一问还成立吗」）。
  分支点同时干两件事：给学习者指路，以及让背解法的人露馅。没有分支点的长题只是一次长练习。
- **解析要写「为什么接着会有下一问」**：法式大题的价值在覆盖与解释，不在挣扎。
  每问的 `source` 指到材料的具体小节，整道题就成了一份带索引的读书路线。
- 小问之间可以复用结论（在题干里写明「可引用第 N 问的结果」），但**判分必须独立**。

## 5. Markdown 与 LaTeX 支持范围

渲染器只支持**受控子集**，请勿使用超出范围的花样语法。

支持：

- 标题 `#`–`######`、无序/有序列表（可嵌套，缩进 2 空格一级）、任务列表 `- [ ]` / `- [x]`
- 围栏代码块 ```` ```lang ````、行内代码 `` `code` ``
- 引用 `>`、分割线 `---`、GFM 表格（`| a | b |` + `| --- | --- |`）
- 强调 `**粗**` `*斜*` `~~删除~~` `==高亮==`
- 链接 `[文本](url)`、图片 `![alt](url)`
- 公式：行内 `$...$` 或 `\(...\)`；块级 `$$...$$` 或 `\[...\]`

不支持 / 会出问题：

- **跨行的行内公式**。`$a` 换行 `b$` 不会渲染 —— 改写成块级 `$$...$$`。
- 脚注、定义列表、HTML 内嵌标签（会被转义）。
- 行内公式里不要用 `$` 转义或嵌套 `$`。

代码块语言标识（决定语法高亮）：`c` `cpp` `cuda` `ptx` `rust` `python` `bash` `asm`
`json` `yaml` `toml` `text`。PTX 用 `ptx`，CUDA 用 `cuda`，未知语言退化为纯文本。

## 6. 校验行为（`python3 tools/check.py`）

ERROR（会让构建失败）：

- `id` / `type` / `topic` 缺失或非法，`id` 重复
- `topic` 不在 `meta/topics.yaml` 中
- `single`/`multi` 的答案不在选项集合里；`multi` 少于 2 个正确项；选项少于 2 个
- `short` 缺 `## 参考答案`；`blank` 答案为空；`problem` 没有小问或小问题干为空
- 出现未知的 `##` 小节名
- 题面为空
- `blankMode` 取值不是 `inline`/`code`

WARN（不阻塞，但应逐条判断）：

- 某行的 `$` 数量为奇数（可能漏写闭合）；`## 答案` 小节内的 `$` 不计入
- 代码围栏未闭合
- `difficulty` 越界或非整数
- 缺 `chapter`、缺解析、`short`/`problem` 缺评分要点
- `id` 前缀与目录名不一致
