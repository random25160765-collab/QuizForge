## 一、系统定位与核心哲学

1. **从“工具”升级为“认知操作系统”**：保留 `QuizForge` 名称，但定位为承载你“学习方法论”的本地认知引擎。
2. **“重型底层 + 轻量前端”**：出题机、沙箱、RAG是重型武器；但UI极致克制，秒开、无冗余弹窗、无多余加载。
3. **“为动脑子的人设计”**：AI 不代替你思考，只作为陪练、考官、资料调度员。认知不可外包。————（这是我和openclaw，hermes等agent在设思想上的区别）
4. **苹果式环环相扣的体验 + 插件式解耦的底层**：用户层追求无缝流转，引擎层保持模块可替换。
5. **对外给用户“枢纽调用面开关”**：用户自主控制 AI 能调用哪些模块（资料/笔记/出题/图谱），把AI边界交还给人。

## 二、架构设计

6. **Chat UI 作为唯一调度枢纽**：所有操作（查资料、记笔记、出题、批改）都从对话发起，后端按需调用模块。
7. **模块先独立，后连接**：资料管理、笔记管理各自独立完整，底层共享数据，由Chat枢纽负责桥接，不强行耦合。
8. **资料库 = “燃料仓”而非“藏书阁”**：资料作为只读的RAG上下文注入器，服务于对话与出题。
9. **Agent 拥有 Edit 权限**：Chat 枢纽不仅“读”，还能“写”和“改”，可直接对笔记进行原地重构（参考Claudian）。
10. **章节树与概念图分离**：章节树（大纲/双链）负责结构；概念图（力导向图）负责连接。两者UI独立切换，不强行融合。
11. **Agent 工具调用采用“挂载式”**：Chat 枢纽本质是“裸脑”，开关控制挂载RAG、笔记读写、出题等工具。

（换句话说我们需要把现在chat页面agent能调用的那些工具，全部做成可组装，可选择的。我想了几个模式，第一种是极简模式，没有任何工具调用，llm无法访问数据库和题库，用户体验和普通的聊天服务无异。第二种是）

## 三、数据与存储

12. **全量采用 MD + YAML 头**：放弃Block模型与数据库JSON。用纯文本承载大纲、双链、代码块，保证绝对可移植。
13. **本地优先（Localhost）**：拒绝上云、拒绝账号系统。数据全部留在用户本地，隐私与安全第一。
14. **资料与笔记物理隔离**：笔记是动态资产，资料是静态参考。各自独立存储，通过后台索引与前端路由逻辑关联。
15. **统一数据抽象层（MD+YAML）支撑多渲染**：大纲、双链、Jupyter格式，本质都是同一套数据的不同视觉呈现。

（这个地方相当于我们结合了zotero的文献管理和obsidian的笔记管理，这两个软件是你设计的重要参考。大纲+双链来源于我深度使用的两个笔记软件：幕布和obsidian。我建议你先把这两个模块做扎实，再考虑接入Chat UI）

## 四、分发与依赖

16. **拒绝 Docker，必须做普通 exe**：用户下载双击即用，所有运行环境本地化。Docker对初学者是灾难。
17. **10MB 启动包 + 云端按需拉取**：主程序控制在10MB内，Python运行时、Numpy、JS库全部云端实时下载（用户必然有网调用API）。
18. **拒绝 CDN，库全本地自包含**：JS库不依赖外网。打包Python运行时和Numpy，但果断绕开Torch（体积大，演示场景用不到）。
（目前沙箱运行python太慢了，你要找一下瓶颈）
21. **用户自填API Key**：绝不承担用户API成本，用户自己配置Key，系统只做调度。

（这个可能涉及封装和技术栈改动。这一步我放弃了之前的云端SaaS服务，转而制作一个local-first app，因为我引入了本地的资料管理与笔记管理的功能。所以之前针对多租户设计的后端就冗余了，可以清掉）

## 五、核心引擎策略

22. **出题机 = 重型武器**：批量生成、沙箱验证、构建公共题库（成千上万道）。无花哨UI，只提供高效终端命令。
23. **Web 日常刷题 = 轻量匕首**：基于对话树的即时出题、边聊边练、错题归因。服务于个人高频自适应学习。
24. **多格式笔记融合（MD + 大纲 + Jupyter）**：大纲快速发散，双链长期连接，Jupyter深度验证。同一数据，不同渲染。
25. **RAG + 向量库本地化**：资料Chunking与入库已完成，本地向量库支撑对话检索，无需云服务。

## 六、体验与交互设计

26. **苹果UI路线 + 原生HTML三件套**：拒绝React/Vue。用纯HTML/CSS/JS实现苹果风极简留白，绝对掌控力，零构建成本。
27. **“驾驶舱”理念**：界面极度跟手，适合高强度用脑。无认知中断，所有工具一臂之内，不抢戏。
28. **资料管理器 = 文件树 + 挂载按钮**：极简文件树，选中后一键挂载到当前对话，AI优先检索该资料。
29. **左侧资料树 + 中间对话流 + 右侧笔记/图谱**：三栏式布局，不切换页面，不打断心流。————（这个涉及UI设计）
