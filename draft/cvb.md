**SwiftLaTeX** 和 **Tectonic** 都是现代 LaTeX 编译工具，目标都是让 LaTeX 更容易使用、更适合自动化/网页环境。但它们的设计思路和适用场景不同。

---

## SwiftLaTeX

**SwiftLaTeX** 是一个基于 WebAssembly 的 LaTeX 引擎，主要特点是**在浏览器里运行 LaTeX 编译**，不需要服务器端安装完整的 TeX 发行版。

- **核心思路**：把 LaTeX 引擎（如 pdfTeX/XeTeX 的变体）编译成 WebAssembly，在浏览器中执行。
- **典型用途**：
  - 在线 LaTeX 编辑器（如网页版 Overleaf 类应用）
  - 需要客户端实时编译、不想把文档传到服务器的场景
  - 教学/演示工具，打开网页就能编译
- **优点**：
  - 纯前端运行，隐私性好，服务器压力小
  - 跨平台，只要有浏览器就行
- **限制**：
  - 需要按需下载宏包/字体资源，首次编译可能较慢
  - 对复杂文档、大量宏包的支持不如完整 TeX Live
  - 项目活跃度和生态相对较小

简单说：**SwiftLaTeX 是把 LaTeX 搬进浏览器的方案。**

---

## Tectonic

**Tectonic** 是一个现代化的、自包含的 LaTeX 编译引擎，由社区开发（最初与 Overleaf 有关联）。

- **核心思路**：一个命令行工具，自动按需下载所需的宏包和依赖，基于 XeTeX 引擎，支持现代字体。
- **典型用途**：
  - 命令行/CI 中编译 LaTeX 文档
  - 自动化构建、持续集成
  - 不想手动安装完整 TeX Live/MiKTeX 的用户
- **优点**：
  - **按需下载**：只获取文档真正需要的宏包，首次编译后缓存
  - **可复现**：可以锁定依赖版本，保证不同机器编译结果一致
  - 单文件二进制，安装简单
  - 支持 Unicode、现代字体（XeTeX 基础）
- **限制**：
  - 不是完整 TeX Live，某些冷门宏包或引擎特性可能不支持
  - 需要网络下载宏包（首次），离线环境需预先缓存
  - 对某些依赖 pdfTeX 特有功能的文档兼容性有限

简单说：**Tectonic 是一个“按需取包、可复现”的现代 LaTeX 编译器。**

---

## 对比总结

| 维度 | SwiftLaTeX | Tectonic |
|------|-----------|----------|
| 运行环境 | 浏览器（WebAssembly） | 命令行/本地 |
| 主要场景 | 在线编辑、前端编译 | 自动化构建、CI、本地编译 |
| 依赖管理 | 前端按需加载资源 | 自动按需下载并缓存 |
| 引擎基础 | pdfTeX/XeTeX 变体 | XeTeX |
| 可复现性 | 一般 | 较强（可锁定版本） |
| 成熟度/生态 | 较小 | 较活跃，社区认可度高 |

---

## 怎么选

- 想做**网页版 LaTeX 编辑器**、在浏览器里编译 → 看 **SwiftLaTeX**
- 想在**命令行/CI 里自动编译**、不想装完整 TeX Live → 用 **Tectonic**
- 需要**完整 TeX Live 兼容性**、大量冷门宏包 → 传统 TeX Live / MiKTeX 更稳妥

如果你能告诉我具体想做什么（比如做在线编辑器、还是搭 CI 自动出 PDF），我可以给更具体的建议。
