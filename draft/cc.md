# 规划下一个大版本

先说清**地形**（按当前库实测，不是文档里的说法）：

| | 实测 |
|---|---|
| 材料 / 点 / 概念 | 60 · 981 · 912 —— 全是 tt-metal 一个学科 |
| **跨材料概念** | **32**（3.5%）—— 其余 880 个只出现在一份材料里 |
| 有序关系（requires + part_of） | **686 条 / 912 概念** |
| 无序关系（co_occurs + contrast_with） | 10091 条（几乎全是按字面算的 code 边）|
| 已发布题 | 1640（迁移层 **0** 道）|
| 其中没挂概念的 | **86** 道 |

由此有四条**内容债**，它们决定了"能不能往上盖新东西"：

1. **"跨材料唯一"这个设计的收益还没兑现**——只有 32 个概念真的横跨材料，图谱页上绝大多数节点是"某份材料里的一次出现"的包装。
2. **前置链连不起来**——平均每个概念 0.75 条有序边。任何"下一步该学什么"的路径推荐，现在都会经常断在半路。
3. **86 道题对图谱不可见**——覆盖率、选题、掌握度都会漏掉它们。
4. **最高一层（迁移）没有内容**——四层里的那个"少而精且必须人审"的层还空着。

## 四个候选版本

| | 目标 | 范围 | 为什么是现在 | 成本 | 怎么验 |
|---|---|---|---|---|---|
| **一 · 让它真的会教** | 从"刷题 + 到期复习"变成"知道下一步学什么" | 补有序边（LLM 判边，已有 `make graph-relate`）+ 补 86 道题的概念挂接 + 图上学习路径（前置链 → 先补哪个、几步）+ 迁移层出题 | 用上了这个项目唯一不可替代的东西（图）；前置链是它的前提，先修前提 | 中（判边的钱可忽略，人的时间在过目） | 图上任取概念能走到根、无环、可传递闭包不矛盾；"根因诊断"从雏形变完整 |
| **二 · 不只一个学科** | 证明这套流水线不是为 tt 定制的 | 选 1–2 个新学科（`reference/`/`Codebase/` 里有现成只读材料）→ 切片 → 抽点 → 建概念 → 出题 → 归类，全程走既有 skill 与 `make drive` | 单学科的"知识空间"说服力有限；也最能暴露流水线的隐性定制 | 中（人力在切片骨架过目与 L3/L4 人审） | 新学科的概念/题/覆盖率真跑出来；流水线不改或只小改 |
| **三 · 检索层落地** | 三路召回 + RRF（向量 + 图 + 规则） | 切片向量索引、图检索走两层边、规则检索、RRF 融合 | 设计已定、是文档里的"下一站"；也是将来"以题搜材料"的底座 | 中 | 构造 query 集看召回率；离线可评估 |
| **四 · 能给别人用** | 从"本机自用"到"可以交出去" | TLS、备份自动化与演练、多用户配额与滥用、密钥与题目版权的边界、上手引导 | 现在的账号与同步已经够一个人用，但离"给别人用"差一整层 | 中高 | 第二个人（不是你）能独立跑起来 |

## 我的建议

**走"一"，但第一刀切在图骨架上**（补有序边 + 补 86 道题 → 再做路径）。理由很直白：候选三里那套检索、候选二里的多学科，都是在"图还很稀"的前提上再铺一层；而"会教"这件事的**全部**价值都吊在有序边上——686 条边撑不起任何路径。

两个提醒：

- **"一"与"三"不冲突但要排先后**：检索层是内部能力（给 agent 找材料段落用），"一"是用户能感觉到的差异。如果这个版本的目标是"让人一看就知道它不只是题库"，"一"更值。
- **顺手能清的零碎**（无论选哪个都能带上）：2 道只有正则没有字面答案的填空、`docs/STATUS.md` 仍是文件式题库时代的写法、以及那份 HIG 六档体检（你说过要看，我一直没执行）。

**在你选之前，有一个问题会改变答案**：这个版本的目标读者还是**你自己**（那就内容深度 + 学习路径优先），还是准备**交给别人用**（那就得先做"四"，否则后面每一次改动都要先补部署与合规）？（这个问题已经自动解决了，因为我做的是local-first app）
