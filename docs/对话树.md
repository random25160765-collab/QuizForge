# 对话树：agent 时代的书

> **一棵树是一个主题的长期探索史。轨迹是唯一的连续物（只有头和尾），
> 树是它当前被修剪成的骨架，摘要是从轨迹里收敛出来的提货点，
> 断点 / 书签 / 批注是三种时间性格不同的标记 —— 而 agent 靠读轨迹的形状
> 来提议「该收、该停、该换个讲法」。**
>
> 2026-09-22。这份不是规格（代码里大多还没做），是**想清楚了的那部分**。
> 它比 `THESIS.md` 更能代表这个软件：THESIS 讲的是学习理论，
> 这一份讲的是一台**能读你学习过程的机器**。

## 一、命题：这不是聊天记录，是一本书

对话树最容易被误解成"聊天记录的可视化"。不是。

**传统书把作者的探索压扁成了线性叙事** —— 你看不到他走过的死路、改过的判断、
绕过的弯。而这棵树**把这些全留着**：分叉、回溯、打转、事后的批注。

于是它有三个传统书没有的性质：

1. **读者即作者。** 树不是别人写的，是自己一层层钻出来的。
2. **以"写"的姿态在学。** 读书是跟着别人的结构走，读完还是别人的；
   写书得把结构自己想清楚 —— 而对话树让**学习过程本身直接就是这本书**，
   不需要事后整理。
3. **书不是翻开的，是长出来的。** 每次重读都能再钻一层，长出新枝。

**"徐徐展开"的确切含义**：读它时默认只展开到**提要**这一层，
要抠细节才往下展开到**全文**。它是一本"**默认是摘要、按需是全文**"的书
—— 纸做不到这一点（纸只有一层），这是它必须长在 agent 上的原因。

## 二、四个层次

| | 是什么 | 时间性 |
|---|---|---|
| **树** | 骨架：当前被修剪成的形态 | 可编辑 |
| **轨迹** | 一条按时间穿过所有节点的**连续曲线** | **只有头和尾** |
| **标记** | 断点 / 书签 / 批注，挂在节点上 | 见 §五 |
| **摘要** | 从一棵子树里收敛出来的提货点 | 可批（见 §六） |

四者的关系不是并列，是**"地 / 路 / 标记"**：

- **轨迹是真相**（发生过的一切，按时间连成一条线）；
- **树是它的当前形态**（从轨迹里修剪出来的骨架，可以再修）；
- **标记与摘要是附着物**（挂在节点或子树上）。

## 三、轨迹：唯一的连续物

### 它不会断，只有头和尾

剪枝剪掉一个分支（只剪故障，见 §六），曲线**按时间顺序直接把缺口缝合** ——
像剪辑删掉一段，前后自动接上。

这条性质反过来**把剪枝的边界钉死了**：只有**不含有效信息的故障**才配被剪、
才配被缝合。剪掉"内容上错的"或"我走错的"会丢东西，**死路是这本书最值钱的部分**。

### 形状 = 深度 × 位置，两者叠加

- **纵轴**：深度（钻下去、浮上来）
- **横轴**：时间
- **分段**：在树的哪一支（位置变化）

所以曲线的形状本身**就是数据**：

| 形状 | 读作 |
|---|---|
| 平滑爬升再回落 | 一次完整的深钻 —— 收敛了 |
| 浅处高频锯齿 | 反复下钻又浮上来 → **没收敛**，或这里被切得太碎 |
| 同一深度长时间横跳 | 在几支之间跳来跳去 → 注意力散了 |
| 停在某深度不再动 | 卡住 / 主动停 / 放弃 —— **三种形状一样，见 §八** |
| 深潜后突然回到根 | 一次大回收（靠**有没有摘要**区分"串起来了"和"走了"） |

### 会话 = 曲线上的一个连续段

- **树**：一个主题，长期活着（可以跨几周）
- **曲线**：访问序列，**跨会话连续**
- **会话**：一次坐下来那段，是曲线上的一个分段

所以"轨迹森林"不是"书架装多棵独立的树"，而是**一片长期生长、
每棵各自跨多次落座的林子**。

### 森林：靠工具访问，不靠预先建边

森林这一层**不需要结构设计** —— **加一组工具**就行（跟访问笔记、资料一样）：

```
mounts 现有的六组：notes / library / graph / quiz / sandbox / web
                          ↓ 加一组
                        trees（对话树）
```

**这把"跨树连接"从"预先建链接"变成了"当场查"** —— 与这个项目一贯的做法一致
（关系靠解析、靠查，不靠标注）。而且它白拿两样现成的：
**挂载开关**（能开能关）与**权限档**（读 / 提议 / 写 / 执行）。

推论：**"查询"模式大概也该挂 trees** —— "我上次是不是钻过这个"是查询类需求，
跟查笔记、查资料同类，不是"学习"模式独有的。

## 四、外置负载：上下文是窗口，不是仓库

### 一般 agent 把上下文当仓库

读进来的资料、聊过的历史、工具结果 —— 全塞在上下文里。于是**窗口大小就是它的记忆上限**，
满了就开始丢最早的东西。

**这里的上下文是窗口**：该装的东西挂在外面，窗口只放"此刻要看的那一小块"。

这是**横向扩展**而非纵向：

- **纵向**（更大的模型、更长的上下文）—— **不是我能控制的**；
- **横向**（在模型外面挂负载）—— **这是我的**。

战略含义：**模型再升级也不会冲掉这套结构**。上下文从 128K 涨到 10M，
外置负载依然有用 —— 因为问题从来不是"装不下"，而是"**该装什么**"。

### 外置了些什么

| | 一般 agent / chat | 这里 |
|---|---|---|
| **记忆** | 上下文窗口（满了就丢） | **对话树**（按轨迹管理） |
| **知识** | 检索片段（一次性） | **资料库 + 笔记**（可挂、可查、有档位） |
| **关系** | 无 | **图谱**（前置链、易混边） |
| **执行** | 工具调用（黑盒） | **沙箱**（浏览器里真跑，结果回传） |
| **长任务** | 主线硬扛 | **子代理**（独立上下文，只回报结果） |
| **压缩** | 摘要 = 截断 | **摘要挂在树上**（可展开回原文） |
| **状态** | 无（只有聊天记录） | **仪表盘**（轨迹形状 + 掌握度） |
| **学习记录** | 无 | **错题本 + 掌握度 + 前置约束** |
| **题库** | 无 | **可读也可写**（见下） |

### 代价：外置了就必须给地图

外置的全部代价是**模型不知道外面有什么**。

上下文里装着全部的时候，它不需要"知道外面有什么"（外面不存在）。一旦东西挂到外面，
**就必须告诉它**：外面有什么、我现在在哪、我探过哪些、还欠什么。

**所以"仪表盘"不是锦上添花，是外置负载的必需品。** 同理：

- **工具组挂载** = 告诉它外面有哪几个抽屉；
- **摘要挂父节点** = 告诉它"你钻过这支配，结论是这句"；
- **记忆按轨迹管理** = 告诉它哪四个部位该记住。

**这三样是同一个动作：给外置负载画地图。**

### 中心是流动的，LLM 是随身的

一个容易搞错的印象是"Chat 是中心"（`draft/c.md` 第 6 条的原话是"Chat UI 作为唯一调度枢纽"）。
更准的说法是：**谁在用，谁就是中心。**

- 今天只想做笔记 → **笔记是中心**，LLM 退到边上。碰到问题过去问一句，**回来接着做**。
- 刷题、翻资料、看图 —— 同理。

**LLM 不是圆心，是随身的那个**：你在哪，它就在哪。

所以 `workbench` 那种"任意窗格"才是这个结构的正确形态 —— 不是因为它有中心，
而是因为**它允许中心随时换**。模式药丸（极简 / 查询 / 学习）同理：
它回答的是"**此刻需要 LLM 干什么**"，而不是"LLM 现在是什么"。

它的身份**由中心决定**：

| 中心在哪 | LLM 是什么 |
|---|---|
| **笔记** | 顾问 / 编辑（起草标签与双链，我逐条收） |
| **题库** | 出题人 / 考官（推题、现编临时题、就着我这次的答法批讲） |
| **资料** | 检索员（找、读、引、核） |
| **图谱** | 分析员（从错题倒查前置链） |
| **对话** | 讲解员（下钻、递归、收敛） |

（`c.md` 里写的"陪练、考官、资料调度员"是其中三种；现在看全了，是**五种身份轮换**。）

### 两条产线：重型武器与随身编辑

**同一件事有两种做法**，它们服务的东西不同：

| | 出题机（流水线） | LLM 现出现改 |
|---|---|---|
| **服务谁** | **所有人**（公共、可校验、可发布） | **只有我**（针对此刻的疑问） |
| **节奏** | 离线批处理 | **跟着对话实时** |
| **优势** | 量与广度 —— 一次一个学科 | **贴身** —— 只补我卡住的那块 |
| **能改什么** | 题库 | **概念图 + 题库 + 掌握度，全都动** |

**所以两条线不是快慢之争，是"铺底 vs 补缝"**：流水线把整个学科铺平，
LLM 在对话里把**具体卡住的那一处**填上 —— 而填的东西立刻进图、进题库、进掌握度。

### 知识库是对话的沉淀物

一般系统里知识库是**静态的**：建好了就在那儿，你只能查它。

这里它**跟着树长**：

- 我钻了一个概念 → 图上**多一个节点**；
- 我问出"这需要先懂 B" → 图上**多一条边**；
- 我在对话里出了道题、答了它 → **题库与掌握度当场变**。

这跟 `THESIS.md` §六 那句"**关系是日志，不是项目**"是同一个思路，
只是范围大得多：**不只是关系，整个知识库都是对话的日志。**

**而两条线真正的不对称在于**：

- 流水线造的是**客观知识**（对谁都一样，因此可以被校验、被发布）；
- LLM 现出现改造的是**我的知识**（带着我的路径、缺口、时机，因此只进"我的"那半边）。

## 五、三种标记：区别在时间性格

| | 本质 | 时间性 | 数量 | 命名 |
|---|---|---|---|---|
| **断点** | **动作**（回溯 + 暂停） | **瞬时**，用完即弃 | 少 | 无名 |
| **书签** | **内容**（下次的入口） | 持久 | 多 | 有名、可搜 |
| **批注** | **附带信息** | 持久 **+ 带时间戳** | 同一节点可叠多条 | 不需要名 |

**断点的性格由"趁手"决定**：要命名就不趁手、要管理就不趁手、几十个也不趁手。
所以它该是**一个键、无名、同时只有几个**。它不是内容，是**动作**。
它有两个用途、本质是一件事（标记一个待回来的位置）：

- **回溯**：我从别处回来
- **暂停**：我主动限制递归深度，回头再来

**书签正相反**：必须有名、能列出、能搜 —— 因为它是**内容**。

**批注是树上唯一"你的声音"**：树上其它节点都是"AI 说的"或"你问的"，都是**当时**；
批注是**你事后怎么看**，是唯一带时间差的层。因为它带时间戳，
所以**同一节点会有多条批注，而且旧的不消失** —— 它让"**理解的变化**"可见。
这跟"树不覆盖轨迹"是同一条价值观：**保留过程，不覆盖**。

**它挂的位置很具体：直接挂在 agent 的输出上** —— 不是挂在提问上，也不是挂在整棵树上。
因为要批的是"**它这句话怎么说的**"，而不是"我问得对不对"。

## 六、三种编辑

### 剪枝：只剪故障

"坏掉的分支"至少三种，处理方式**不该一样**：

| 坏法 | 该不该剪 | 为什么 |
|---|---|---|
| **技术故障**（网络断、生成失败） | **剪** | 没有信息量，留着只是噪声 |
| **AI 答错了** | **未必** | 它是"AI 会在哪骗人"的证据 —— 练审读正好用它 |
| **我走错了路** | **绝不能剪** | 死路是这本书最有价值的部分 |

配得上"缝合"这个动作的，**只有第一种**。

### 摘要：LLM 起草，我来批

跟 `edit` 工具同构：**提案 → 看 diff → 接受 / 拒绝 / 改，接受之前原状不变**。

这套机制**天然兼容分层**，不需要两套流程：

- 浅的、顺手钻的 → **自动接受**（我不看）
- 深的、关键的 → **我逐条批**

**收敛 = 写摘要。** 所以"什么时候该收回分支"这条自律要求，
在系统里变成了一件**有产出的事** —— 自律变成了机制。
（`draft/g.md` 里那句"递归学习法需要**注意收敛时机**"，就是从这里落地的。）

**它挂的位置也很具体：挂在父节点上。** 一整支子树钻完，摘要挂回它的上游 ——
于是"回到主线时我手里带着什么"是**结构决定的**，不用临场交代。

（**批注挂 agent 输出、摘要挂父节点**：位置不同，层级也不同。所以一个节点可以
**同时**有摘要（它是一支的入口）和自己的批注（它的内容被评过），两者不冲突。）

### 批注：只增不减

见 §五。它是"加"，与剪枝（"删"）正好相反。

## 七、记忆按轨迹管理

### 先说一条管全篇的分工：机械 / 发现 / 姿态

（它从这一节长出来，但管的不只是记忆。）

| 类 | 例子 | 归谁 | 为什么 |
|---|---|---|---|
| **机械** | 算 hash、格式化、重试、建索引 | **系统** | 没有姿态成分，谁做都一样 |
| **发现**（信息） | "隔壁还有一支"、"已经三小时了" | **系统** —— 但只送到我面前 | 是数据，不是决定 |
| **姿态** | 打暂停、切记忆档、标书签、判"这支钻完了" | **我** | **做这件事本身就是管理自己** |

第二、三行的分界最要紧：系统可以**发现**"我连续三小时了"，
但**"该不该停"是一个姿态** —— 只有我能按。

**姿态为什么不能外包**：外包了，**作者身份就外包了**（§一）。
树之所以是我的作品，不是因为它记了我**说了什么**，而是因为那些分叉、暂停、
收敛**都是我亲手按的**。系统替我按，它就退化成"一份学习过程的记录"。

（原先我把打标签、记账、提醒这一类叫"**杂事**"、说要交回系统 —— **那是我说错了**：
"不需要判断"不等于"不该由我做"。这一节末尾那句已按这条总纲修正，
而由此暴露的漏洞写进了 §九。）

### 一个区域，一刀切准

**问题**：我回溯到主线之后，子树里讲的东西不该被忘掉。

**好消息**：树天然给出了记忆该不该留的判据 —— **一刀就切准**：

| 树的部位 | 记忆怎么处理 |
|---|---|
| **当前路径**（根 → 我现在在哪） | **全留**（这是"我在哪"，丢了就断线） |
| **走过的分支** | **压成摘要挂回父节点**（细节可展开，但不必常驻） |
| **没走过的分支** | **只留存在感**（"这儿还有一支没钻"） |
| **剪掉的故障** | **不留**（无信息，缝合掉正好） |

"回溯之后子树忘了"靠第二行解决：**不是把原文一直抱着，而是钻完就压成一句话挂回去**。

### 记忆范围：三档，默认「存在感」，逐轮可切

上面那张表说的是**存法**（哪种部位留什么、摘要在树上挂在哪儿）。但还有一层**装载** ——
**存下来的那些，这一轮的窗口里放多少？** 具体说：

> 我在某一支上钻的时候，**兄弟分支**（我没在走的那几支）的话，这一轮要不要让模型记住？

两个极端都不对：

- **一点都不带**（上下文里只有从根到当前节点的路径）—— 最干净，但**"我刚刚在隔壁钻过的那一支"就白钻了**，每换一支都失忆；
- **全带**（整棵树塞进去）—— 什么都不忘，但**必爆**。

所以要切的不是"带不带"，而是**切在哪儿**。三档：

| 档 | 上下文里有什么 | 谁知道隔壁有东西 |
|---|---|---|
| **不带** | 只有当前链的正文 | 没人 |
| **带存在感**（默认） | 当前链正文 + 一句「隔壁有 X，结论 Y」 | **我，以及模型** |
| **全带** | 真的塞进来 | 我，以及模型 |

三档动的是**当前路径之外**的部分（当前路径永远全留 —— 那是"我在哪"，丢了就断线）；
上面那张表的第二、三行，就是它拧动的对象。

这是**给模型的记忆做细粒度管理**：逐轮可切（跟模式药丸同一个机制 —— 它回答的是"**此刻要模型怎么待**"），
**而且可粘住** —— 在某条枝上切到某一档，它就粘着，直到我切回来。**不是每轮重选。**

#### 为什么这个开关只能由人握着

因为**模型在原理上做不了这个决定**：要决定"要不要把隔壁那支带上"，前提是**知道隔壁那支存在**；
而没带的话，它就在当前上下文之外 —— **模型看不到自己没看到的东西**。

鸡生蛋：**它没法提议展开一个它不知道存在的分支。**

由此也就知道了"要求更高"这件事该落在哪儿 —— **让发现自动，让决定廉价**：

- **发现**（"隔壁还有一支"）交给系统，因为它不要钱（那句话本来就在 —— §六 的摘要挂在父节点上）；
- **决定**（"这轮带不带"）交给人，因为它要判断 —— 而判断正是 §十一 讲的那种元认知。

**这就是「存在感」这一档为什么必须存在**：它不是"省 token 的妥协"，
而是**让细粒度控制得以成立的前提**。没有它，模型连提议的资格都没有；
而如果只有"不带 / 全带"两个极端，我就得**时刻记着自己还有哪些分支没带** —— 那才是真的累。

（说明白：这个旋钮确实是**又一道判断题**（§十一 那种），它抬高了要求，不假装它不抬高 ——
但这正是**该抬高的那部分**。哪些该抬高、哪些不该，见本节开头那条总纲。）

### 仪表盘：给模型看的轨迹

把轨迹状态实时报给前台 LLM。它看到的四样：

- **我在哪**（当前节点、深度）
- **我怎么来的**（根到这里的路径 —— 强记忆）
- **我探过什么**（各分支的一句话摘要 + 各自深度）
- **我还欠什么**（未探的分支、断掉的地方）

**它不是工具，是每轮自动挂在系统提示里的仪表盘**（`recursion.dashboard()`，2026-09 从
工具改过来 —— 用户原话："它不应该被做成工具，对话轨迹是 llm 长期可见的用户信息
仪表盘"）。工具是**要模型想起来的**东西，而"这个人在怎么学"是它说每句话时都该带着的
背景：做成工具时，模型只在被明确要求复盘时看一眼，平时对这位用户一无所知。

两条随之而来的规矩：**挂载模式不影响它**（极简模式只是"没有工具"，不是"不认识这位
用户"，所以那份提示词同样带着仪表盘）；**体积按树的自适应**（长对话只给数字与下钻
清单，骨架只在 40 条以内的短对话里给 —— 它是每轮都要背的，不是查一次就丢的）。

**传统 chat 的模型是"接着上文说"，这里是"看着地图说"** —— 从线性记忆
换成结构化记忆，而结构是现成的（就是那棵树），不用另造一套。

## 八、"停住"不等于"逃了"

曲线上某一处停住，形状上看是**同一件事**，但实际有三种：

| 状态 | 谁定 | 系统怎么办 |
|---|---|---|
| **故障** | 系统（网络断） | 剪掉、缝合 |
| **暂停** | **我**（主动限深 / 先去干别的） | **原地留着**，等我回来 |
| **结束** | **我**（钻完了） | 收摘要 |

**系统不许替人下判断。** 一旦把停住标成"逃避"，它就**在对人下判断** ——
而那三种形状一模一样，**只有我知道是哪种**。

**暂停应该是默认态**：故障系统自己认得出来，"结束"要等我明确说完了，
**剩下的都是暂停**。于是"**节点是否完成**"可以**滞后很久才确定** ——
跟批注带时间戳是同一个态度：**不急着盖棺**。

（顺带说：**判断"这是暂停还是结束"本身就是一道没有标准答案的判断题** ——
它正是 §十一 讲的那种负担。系统能做的只是别替我判断、并把决定权交回来。）

## 九、收敛时机：双向触发，一个面板

**不是我选"默认悬着"还是"每次留话"，而是两个入口、一个面板**：

- **agent 主动提议** —— 跳一个面板让我选（结束 / 暂停 / 继续）
- **我自己停** —— 随时可以

它跟两个既有模式是同一个范式（第三次出现）：**机器提议、人裁决**
（另两个是 `note_suggest` 的"只提案、人点才写"、迁移题的"点名请人过目"）。

**为什么这个设计对**：同一份观察（曲线停住了），
**判决**和**提问**的差别就是"AI 是替身还是陪练"。陪练会问你要不要歇，
不会替你决定该不该歇。

**agent 凭什么知道该提议？** 只能靠读轨迹形状（见 §三的表）：折返变密、
同一深度停太久、深度已够、话题明显转移。

**面板的音量**：要能被看见（否则等于没提），又不能抢戏
（`c.md` 第 27 条："无认知中断，所有工具一臂之内，不抢戏"）。
所以它大概不该"跳"出来，而该**在边上亮起来** —— 想理的时候点开，不理就搁着。

### 音量不是固定设置，是随我状态浮动的量

固定的音量一定会错：定得低，在我最需要它的那一刻等于没提；定得高，
在我清楚的时候就是噪声。**而这两件事是同一件事** ——
我最需要它的那一刻，恰恰是我最听不见它的时候。

因为**自我觉察本身就是被消耗的资源**：清醒时我知道"我累了"；被消耗时，
我连"该觉察一下"都想不起来。"忘记睡眠"不是不想睡，
是**在那个状态里判断不出自己需要睡**。所以"姿态归我"（§七 总纲）这一条，
靠我一个人是兜不住的 —— **我越撑不住，我按那个按钮的能力越低，而那正是需要它的时刻。**

音量因此该跟状态走：

| 我的状态 | 它的音量 |
|---|---|
| 节奏正常 | **不响**（我自己管，它别插手） |
| 连续 90 分钟没动、也没停 | 边上**亮一个点** |
| 三小时还在下钻 | 亮起来 + 一句事实（"已经三小时了"），**一次点击**就能暂停 |
| 凌晨一点 + 已经五小时 | **翻转默认**：不自动接着给新内容，要我说一句"继续" |

最后一档是唯一有牙齿的，但它**不是禁止，是翻转默认** —— "继续"从免费变成要说一句；
我随时能说，说了一切照旧。**它不替我决定学什么，只是不让"接着熬"成为不用决定的默认选项。**

这也划清了"互动"和"代替"的界：**它调的是音量，不是判断。**
音量之所以能交给它，是因为**发现**本来就归它（§七 总纲）—— 它不会累、不会忘、
不会被我自己的状态吃掉；而"停不停"仍然是我的姿态。

（医疗、睡眠这类**生理边界**，是这条音量的极端档：**学习判断错了，损失落在我学得不好，
可恢复；生理边界崩了，损失落在身体，不可恢复。** 所以"认知不可外包"不覆盖它 ——
不替我想"该学什么"，和"不看着我把眼睛熬坏"，是两条不同的规矩。）

## 十、轨迹的第二个用途：智适应的基础

轨迹分析**先用于"提议收敛"**（§九），这比智适应更早落地 ——
因为它**不需要判分、不需要题库**，只要曲线。

而它与"做题式智适应"是**互补**关系，不是替代：

| | 做题式智适应 | **轨迹式智适应** |
|---|---|---|
| 数据从哪来 | 要**主动去做题** | **学的时候自然产生**（对话就是数据） |
| 什么时候有 | 做完之后 → **滞后** | 当场就有 → **实时** |
| 需不需要判分 | 需要（判对错才能更新掌握度） | **不需要**（形状本身可读） |

**体检报告 vs 实时心率。** 而心率能抓的、体检抓不到：**体检只在你"决定去做题"
时才发生，而转移注意的人恰恰不会去做题**。

它适应的也不只是"选题"，还有**讲法与入口**：

| 轨迹读出 | 该适应什么 |
|---|---|
| 某子树里密集打转 | 不是"再练"，是**换个讲法** —— 这里没被讲明白 |
| 主线↔支线反复折返 | **收敛时机**（这正是递归学习法唯一的已知弱点） |
| 曲线突然终止 | **换入口**，而不是"再推一道题" |
| 曲线短且直 | 顺 → **可以加速**，不用停在这儿磨 |

**形状还能对比**：同一主题的两遍（长且折返 → 短且直，这是"学会了"的直接证据）、
不同主题之间（哪一科更"打转"）、不同时期（学法在变）。

## 十一、VN 的比喻：一场要自己抉择的游戏

它像 visual novel，**不只是因为"分叉 + 存档"，而是因为每一步都在做抉择** ——
而 VN 的抉择有三个性质，学习里的抉择一个不少：

1. **没有标准答案** —— 谁也不知道选哪条线更好。什么时候收、这支钻多深、
   哪条留哪条剪，全都没有正解。
2. **不可逆** —— 时间花掉了就是花掉了（但可以读档：回溯）。
3. **累积** —— 选择叠起来，成了结局。

### 所以"对人的要求很高"，不是"要多花时间"，是每一步都是判断题

| | 低要求的方法 | 这套 |
|---|---|---|
| 钻多深 | 教材 / 课纲 / AI 定 | **我定** |
| 什么叫"懂了" | 考过、做过就算 | **我自己判断收敛** |
| 哪条留哪条剪 | 不用管 | **我决定** |

而最狠的一点：这些判断题**没有对错反馈** —— 不像选择题有答案。
所以它要的不是知识，是**元认知**：对自己的理解状态做实时判断。

（"递归学习法"里，"递归"是形式，**"自我要求"才是实质** ——
每走一步都在自问"够了吗、偏了吗、该收了吗"。）

**而"灵活"和"要求高"是同一件事的两面**：不给路线，所以灵活；
不给路线，所以你得自己找路。

### 已经对得上的几个机制

VN 里早就有的东西，这里一一对应：

| VN | 这里 |
|---|---|
| 读档点 | **断点** |
| 折角 | **书签** |
| 已读标记 + 快进 | **摘要**（收过的分支压成一句，不必重读原文） |
| 分叉的选项 | **下钻 / 不钻** |
| 结局 | **你这棵树** |

### 攻略问题：AI 直接给答案，就是给攻略

VN 有攻略，但**照着攻略玩，游戏就没意思了**。

**AI 直接给答案，就是给攻略。** 所以"认知不可外包"和"机器提议、人裁决"，
本质是**拒绝攻略** —— 要的不是通关，是**玩这一遍的过程**。

**"结局是所有抉择的累积"在这里就变成**：**你的知识结构，就是你所有抉择的累积。**
所以那棵树**不是记录，是作品** —— 它是几十次判断题的答案叠起来的形状。

## 十二、skill：口吻、流程、纪律

**skill 是一段提示词，不是代码** —— 加一个能力不用动系统，写一段话就行。

这是 §四 那条思路的又一个实例：**把"讲授法"从模型里外置出来**。
模型的内置风格改不了（它是什么就是什么）；skill 把这层搬到外面，
于是它变成一份**可以随时加、随时换、随时扔的清单** ——
"不同场景都有用处"的前提，正是它在外置。内置就意味着只有一种。

### 三种形态

| 形态 | 它改什么 | 类型 | 怎么用 |
|---|---|---|---|
| **口吻** | 它**怎么说** | **状态**（挂着，持续生效） | 装 / 取 |
| **流程** | 它**按什么步骤走** | **动作**（有开始、有走完） | 发起 / 走完 |
| **纪律** | 它**不许做什么** | **状态**（挂着，持续生效） | 装 / 取 |

**口吻和纪律是同一类**（都是状态），**方向相反**：口吻调音色，纪律划边界。
纪律的例子："别直接给答案"、"先问我"、"只许引我读过的东西" ——
它不改它怎么说，它改它**能做什么**。

**流程与前两者的差别在时效**：口吻和纪律挂上去就一直生效；流程是有始有终的一件事。

### 口吻 = 作用域 + 环境变量

**它挂在节点上，沿树继承，可回退。**

这是"粘在哪一层"的答案：**不是整棵树，是一个子树**。因为同一棵树里，
这一支在抠证明（要精确），那一支在建直觉（要大白话）—— 树级兜不住。
而**一个对话就是一棵树**（§三），它可能连着几天都在转 ——
所以"今天在这支上换个说法"是常态需求，**不能靠全局重置来解决**。

**"回退"有两种，都要有**：**走出来**（离开那个子树，自动回到上层设置）、
**显式取下**（在当前节点取掉）。

**这个机制已经出现第二次了**：

| | 挂在哪 | 作用 |
|---|---|---|
| **记忆范围**（§七） | 节点 | 从这里往下，上下文装多少 |
| **口吻** | 节点 | 从这里往下，你怎么说话 |

**所以：树不只是一份记录，它还是一棵"设置的作用域树"。** 两者是同一类东西 ——
沿树继承、可覆盖、可回退。这不是巧合：树本来就是这里唯一的结构，
凡是"从这里往下都该这样"的东西，都该挂在它上面。

### 动作 vs 状态：为什么学习法该做成 `/`

| | 形态 | 怎么用 |
|---|---|---|
| **口吻 / 纪律** | **状态**（背景） | 装 / 取 |
| **学习法** | **动作**（事件） | 发起 / 走完 |

三个理由，一个比一个硬：

1. **它有步骤** —— 费曼法是"我讲 → 它戳 → 我回炉"，有开始也有"走完了"。
2. **它切换主体** —— 费曼法里讲的人**是我**，不是它。这是**事件**，不是背景设置。
3. **它要求我行动才成立** —— 我不讲，它就没法进行。所以**必须由我召唤**。

`/费曼` 这一下**本身就是"我要开始学了"的姿态** —— 落回 §七 那条总纲：
**姿态归人，而学习法是姿态。**

（顺带：这也解释了为什么口吻不该做成 `/` —— 我不是"发起一次大白话"，
我是"接下来都说大白话"。一个是动词，一个是形容词。）

### 经典学习法都能做成 `/`

| 命令 | 它做什么 | 谁在动 |
|---|---|---|
| **费曼法** | 我讲，它戳我卡住的地方 | 我 |
| **苏格拉底** | 它只反问，不给答案 | 我 |
| **反例法** | 逼我找一个反例来测试自己的理解 | 我 |
| **类比法** | 强制找一个类比，再检验它在哪里失效 | 我 |
| **SQ3R** | 概览 → 提问 → 精读 → 复述 → 复习 | 我 |
| **康奈尔笔记** | 按三栏结构记，强制写"摘要"和"疑问" | 我 |

**共同结构很明显**：有步骤、有"走完了"的状态、**都要求我做事**。
它们是**程序**，不是设置 —— 所以天生是 `/` 命令。

**这也是它们值得做的地方**：这些方法的价值从来不是"知识"，是**逼迫**。
做成命令，就是把这股逼迫**变成随时可召唤的**。

### 口吻的两型（以及滤镜不是完全透明的）

"大白话"和"掉书袋"（**旁征博引**，不是术语堆砌）是一对真正的对比 ——
**两者都在"用已知解释未知"，区别只是用谁的已知**：

| 口吻 | 用谁的已知 |
|---|---|
| **大白话** | **我的日常经验**（拿我熟悉的东西打比方） |
| **旁征博引** | **知识共同体的积累**（这本书说过、那个领域对应什么、历史上怎么演化） |

所以它们"不同场景都有用处"：**新领域、要建直觉 → 大白话**（先站住）；
**已有底子、要定位脉络 → 旁征博引**（知道它站在谁的肩上）。

旁征博引其实是**更难**的一种讲法 —— 它要求讲的人真的知道那些出处，随便引就露怯。
**它是信息密度高的那种，不是门槛高的那种。**

**最后一条要说清**：滤镜不是完全透明的。口吻**必然带着内容取舍** ——
大白话讲不了某些证明细节。但**能看见的取舍是我的选择，看不见的取舍是它在替我做主** ——
这正是口吻必须由我装、并且随时能取下的原因。

## 十三、日程与时间：给地图补上缺的那条轴

它是 §四 那张"外置负载"表里一直空着的一格。

### 地图上缺的那条轴

§四 有句话："**外置了就必须给地图**"。而这张地图上有：

| 轴 | 由谁提供 |
|---|---|
| **空间** —— 我在哪棵树、哪个节点、多深 | 对话树 |
| **知识** —— 掌握度、错题、前置链 | 图谱 / 错题本 |
| **资料** —— 笔记、库、检索 | 笔记 / 资料库 |
| **时间** | **← 这一格一直是空的** |

所以在此之前，"你可以今天学三小时"这种话**说得出来，但站不住** ——
它不知道我今天有没有三小时。**地图上缺一格，规划就只能空转。**

### 规划：从"无限"到"在约束下"

| | 没有日程 | 有日程 |
|---|---|---|
| 它能说 | "你今天可以把这一节过完" | "明天 10 点后有 40 分钟，这一节刚好塞得进去" |
| 依据 | 无（默认时间无限） | **我的真实可用时间** |
| 结果 | 空话 | 可执行的安排 |

### 它也是"音量"的数据源

§九 那张随状态浮动的音量表，要的是三样东西：**已经连续多久了**、**现在几点**、
**明天要不要早起**（所以今晚几点该停）。这三样以前全靠猜，或者干脆没有。

**没有它，§九 那条音量规则只有形状、没有燃料。**

### 森林层终于可调度

**多棵树之间唯一可比的量是时间。** 每棵树都要吃时间。

- **树内**的问题是"**怎么钻**" —— 靠轨迹形状回答（§三）；
- **森林**的问题是"**排哪个**" —— 靠**时间和优先级**回答。

没有时间感的时候，"森林"只是**并存**；有了日程，它才能**被安排**
（这周主攻哪棵、那棵先搁着）。**日程是森林那一层一直缺的输入。**

### 权限与边界

它是**最私人的一份数据** —— 比笔记私人得多：笔记是"我学过什么"，
日程是"**我什么时候在哪儿、要干什么**"。所以：

- **默认只读** —— 它知道，但不碰；
- **要写就显式** —— "把这节排到周四"这类动作走 `note_suggest` 那种
  **"只提案、人点才写"**，不默认动我的日历；
- **随时能断开** —— 这份负载撤掉，其它一切照常跑（外置负载的通用性质）。

**它不该沉淀进任何东西**：日程是**输入**，不是产出 ——
不像笔记会进图、进题库，日程读进来的东西不该改变我的知识库。

## 十四、还没定的

**摘要与轨迹**

- **摘要的粒度**：一个分支一篇，还是按深度分层？
- **摘要的所有权**：位置已经定了（挂父节点），但"我改过之后，它还算 LLM 起草的吗"
  —— 这个还没定。（批注挂 agent 输出、摘要挂父节点，两者的挂法已经定了，见 §五 / §六。）
- **轨迹的可视化**：**形式定了 —— 以「播放」为主**。静态全图不是不能要
  （就算画出蜘蛛网也**可以接受**，那不致命），但**播放更好**：
  因为"徐徐展开"本来就是个动词，不是一张图。还没定的是播放的**具体形态**
  （怎么拖时间轴、当前节点怎么亮、分支按什么节奏展开）。
- **"提议收敛"的判据阈值**：折返多少次算多、停多久算久 —— 现在全是定性。

**记忆范围（§七）**

- **记忆范围旋钮长什么样**：三档已经定了，默认「存在感」也定了；
  没定的是**它在界面上挨着谁** —— 跟模式药丸并成一维（"极简 / 查询 / 学习" × "不带 / 存在感 / 全带"），
  还是各占一个独立开关。两者是正交的（一个管工具边界、一个管记忆边界），
  合并意味着**一次点两个格**，独立意味着**两个控件**。

**skill（§十二）**

- **口吻的清单**：先做哪几个？"大白话 / 旁征博引"够不够撑住日常，
  还是要更细的（先结论后推导、举代码例子、只用类比不写公式…）。
- **口吻能不能叠**：装两个（"大白话" + "旁征博引"）是互相冲突，
  还是可以合成一种"浅白地旁征博引"。
- **纪律与权限档的关系**：§四 里那套"读 / 提议 / 写 / 执行"是**挂载级**的硬权限；
  纪律是**提示词级**的软约束。两者要不要统一，还是各管一段。
- **skill 从哪来**：只我本地写，还是能收藏 / 导入别人的一篇提示词。

**日程（§十三）**

- **数据从哪来**：自己维护一份本地日程，还是读系统日历（ICS / CalDAV）？
  前者简单、离线；后者不用重复录入，但要处理同步与隐私。
- **粒度**：是"哪几个时段空着"这种粗粒度，还是要到"这件事预计 40 分钟"的任务级。
- **它和"生理边界"的关系**（§九）：作息算不算日程的一部分 ——
  如果算，那"该睡了"和"明天有会"就是同一份数据的两种读法。
- **写回的能力到哪一步**：只到"建议时段"，还是可以真的占一个位置（且必须我能一键撤销）。
