# 分发工作流

> **唯一事实是 WSL/Linux 侧这份仓库。** Windows 侧那个目录只是**构建镜像**，不许手改。
> 打包必须在 Windows 上跑（PyInstaller **不能交叉编译**），所以整体是"这边开发、那边出包"。
>
> 最后更新：2026-11-08

## 零、两个上下文，别混

| 上下文 | 怎么起 | 数据在哪 | 给谁 |
|---|---|---|---|
| **开发通道** | `make dev`（本机 uvicorn，热重载） | 仓库里的 `data/` | 只有开发者 |
| **桌面包** | `make dist`（Win）/ `make dist-linux`（Linux） | `~/quizforge/`（Windows：`%USERPROFILE%`） | 用户（用各人自己的密钥） |

2026-11-08：**分发通道删除**，只有一个版本（老的 `~/quizforge-beta/` 首次启动自动迁移）。

**开发通道就是"localhost 起 web 服务"**：改代码即时生效，用的是仓库那份数据，
跟分发的那个包**互不干扰**（数据目录不同）。分发走的是**安装包**。

> 两个库不是同一个：桌面包第一次启动时 `%USERPROFILE%\quizforge\quizforge.db` 是**空的**。
> 配好 Turso 之后头一轮自动同步（启动约 5 秒起）会把题库与材料拉下来（`bank_cloud` /
> `library_cloud` 整包）；**没配 Turso** 时才需要拿题库包导（第七节），不是"打开就有"。

## 一、一条命令

```bash
make win-setup     # 首次（只做一次）：查 Python、建 venv、装依赖、查 Node —— 幂等
make dist          # 出桌面包 + 安装包（Windows；唯一版本）
make dist-verify   # 静默重装一遍，把装好的应用逐页截图（白屏就看它）
make dist-check    # 桌面上那个包是不是当前代码打的（不打包）
make dist-linux    # 出 Linux 的包（当前平台就是 Linux，不用绕 Windows）
```

`make dist` 内部按顺序做四件事，**顺序不能换**：

| 步 | 做什么 | 为什么必须在这一步 |
|---|---|---|
| 1 | `make web` | 前端产物要新（`theme/` 改动没构建就同步过去，包里就是旧界面） |
| 2 | 镜像同步（`build/sync_win.py`） | **先同步再打包**：否则打出来的是上一版代码，症状是"改的东西没生效"，离原因很远 |
| 3 | 在 Windows 上 `build/package.py build` | PyInstaller 不能交叉编译；用 `%USERPROFILE%\Desktop\QF_dist\.venv` 里那个 python（脚本自己会调） |
| 4 | 自检 + 桌面外壳（Electron）→ 安装包 + 归位 | 后端自检（接口 / 静态页 / 真实题库 / 首启建库）过了才继续；外壳装的就是第 3 步那个 exe |

产物（都落在桌面，也在仓库 `build/dist/` 各留一份）：

| 文件 | 是什么 |
|---|---|
| `QFStudio Setup <版本>.exe` | **安装包**，双击装一次；装完从桌面/开始菜单的 QFStudio 启动 |
| `quizforge.exe` | 后端本体（约 42 MB）。单独跑也行：它自己起服务，用系统浏览器打开 |

**为什么还要后端本体**：外壳只是把那个服务装进窗口里；排障时直接跑 exe、
用浏览器打开 `http://127.0.0.1:<端口>`，比在安装版里找原因快得多。

## 一点二、构建戳：怎么确认"给用户的就是开发时那一份"

用户提过一个很实在的问题：**开发端有、exe 里没有**，而且每次都得来问。
那种情况下当时没有任何地方看得出来 —— 只能靠人问。现在固化成三层：

| 层 | 在哪 | 作用 |
|---|---|---|
| **构建戳** | `api/web/build.json`（由 `make web` 写） | 戳 = 前端产物 + `api/app` 源码一起算的哈希（12 位）；内容一样 → 戳一样 |
| **包自己报** | `/api/health` 的 `build` 字段 | 跑起来就知道"这份包服务的是哪次构建" |
| **随包留一份** | 桌面上的 `quizforge.stamp` | **不用启动**就能比对 |

于是"同步"从"靠记得"变成"能核对"：

```bash
make api-dev       # 起开发服务前**必构建前端**（以前不构建，看到的是上一次的产物 —— 实测踩过）
make dist          # 打包；自检里比对"包里那份 vs 仓库那份"，不一致直接报错、不发
make dist-check    # 桌面那个包是不是当前代码打的（一句话问清楚）
```

`make dist` 里那句"不一致就报错"是关键：**结构上**由镜像同步的逐文件哈希保证，
**结果上**由自检再核对一次 —— 两道都过，才算"给用户的就是开发时那一份"。

## 一点五、发版前：对**真 exe** 跑一次对话烟测

```bash
make smoke           # 起包 → 发一句「你好」→ 看落库与回复 → 关掉
```

**为什么单独这一步**：打包自检刻意不碰 AI（只验"能启动、能读、能写"），
而"对话"这条路上还有几个环节只在真跑时才暴露。内测包第一版就死在这里 ——
`messages.id` 在库里是 `BIGINT`（SQLite 上不自增），一发「你好」就
`NOT NULL constraint failed: messages.id`，**而当时的自检全绿**。

它走一次模型（花钱），所以不挂进 `make dist`；发版前手动跑一次。
通过的输出长这样：

```
健康检查：ok=True 题数=1623
流里的事件：delta,done,start,tool,usage,user
会话里存了 2 条消息：
   #237 user: 你好
   #238 assistant: 你好。你现在手里是 tt-metal 这条线 —— …
烟测通过：消息落库 · 模型有回复 ✓
```

## 一点四、双击之后看到什么

安装包装完之后，双击图标起来的是**外壳窗口**（`desktop/`，Electron）：

1. 外壳挑一个空闲端口，把 `resources/backend/quizforge.exe` 作为子进程拉起来
   （`--port <p> --no-browser`）；
2. 轮询 `/api/health`，通了才开窗口（不通就弹框说原因，不留一片白）；
3. 窗口加载 `http://127.0.0.1:<p>/`（首页跳 `chat.html`）—— 页面、接口、SSE 全在
   同一个源上，不踩 `file://` 的跨域。

后端起不来时，`starting.html` 那条路仍然可用：直接双击 `quizforge.exe`，它会把
启动页开在系统浏览器里 —— 那里的启动检查与 `/api/startup` 是同一份数据
（数据目录 / 库与表 / 题库 / 前端产物 / 密钥 / Python 运行时）。

**没有终端了，"出错去哪儿看"有四个落点**：

| 落点 | 看什么 |
|---|---|
| `%APPDATA%\quizforge-desktop\shell.log` | 外壳：后端起没起来、每页的 `probe`、`did-fail-load` |
| `%APPDATA%\quizforge-desktop\window*.png` | 外壳抓的截图（首屏 `window.png`，逐页探针 `window-<页名>.png`） |
| 数据目录 `%USERPROFILE%\quizforge\quizforge.log` | 后端：端口、数据目录、请求与异常 |
| 系统错误对话框 | 起不来时的最后一句话 |

## 二点三、开发端与桌面包的差异从哪儿来（三类）

用户的原话："有一些东西在 web UI 上和在 electron 里行为不一样……这种行为差异很普遍。"
**不是 Electron 与浏览器不一样**，差异只有三个来源，逐条对得上就不会再"看着像玄学"：

| 类别 | 差别是什么 | 表现 | 怎么防 |
|---|---|---|---|
| **① 数据不同** | 桌面包的数据目录是**新的空库**（`%USERPROFILE%\quizforge`），开发端是攒了几千道题、几十条会话的库 | 空库/空会话才走得通的分支没人验过：整页白屏、滤镜药丸不出现、"题库还没有题目" | 空数据是**一等场景**：状态屏必须能画（`boot.js`）、首屏必须自己把工具栏补齐（`renderEmptyThread`）；`make dist-verify` 就是拿**临时空库**跑的 |
| **② 只读资源没进包** | `pipeline/`、`tools/` 这些是 `api/` 的**兄弟目录**，开发时永远找得到；打包后只有 `--add-data` 带进去的才在 | 界面上**少一块**（资料页"抓正文"点不动），接口全绿 | 定位一律走 `REPO_ROOT`/`RESOURCE_ROOT`（打包后 = 解包目录）；新加一个"跟着包走的目录"就同步加 `--add-data`；启动检查里那条**只读资源**会当场报出来 |
| **④ 滤镜是用户数据** | 「滤镜」不随包发：它存在**数据目录**（`<数据目录>/lens/*.md`），开发机上那 10 条只是从仓库 `lens/` 拷进去的**预置** | 桌面包第一次启动**一条滤镜都没有**（这是要的默认，不是漏打包）；药丸照样在，点开能新建 | `lens.seed_presets()` 只在不冻结时拷一次；打包**不带** `lens/`；自检只要求 `/api/chat/mounts` 里 `lens` **取得到**，不比条数 |
| **③ origin 不稳定** | 浏览器按 origin（含端口）存 `localStorage`；外壳原先每次随机端口 = 每次都是"新站点" | 主题、侧栏宽度、"深度思考"这些开关**每次启动回到默认**（开发端固定 8100，所以粘） | 外壳先试固定端口 `8731/8732/8733`，都被占才退回随机（并在 `shell.log` 里说明） |

## 二点五、白屏怎么验（`make dist-verify`）

**白屏只能拿"渲染出来是什么"说话**：接口全绿、文件都在，页面上照样可以是空的。
实测撞过两次：

* 数据目录是空的时候，对话页**一片空白**（`boot.js` 的"已经有内容就别覆盖"
  把每一屏状态都挡掉了，而 `#app-root` 里那句注释就算"内容"）；

`make dist-verify` 做的就是这个：静默重装 → 清掉外壳的 userData → 用**临时数据目录**
起后端（= 新用户的空库）→ `QF_SHELL_PROBE` 让外壳依次打开 chat / quiz / library，
各探一次状态、各抓一张图 → 把截图拷到 `/tmp/qf-install-shots/`。判据是每一页的
`rootKids` 与 `text` 都不为空。

## 三、镜像的规矩（`build/sync_win.py`）

* **只朝一个方向**：WSL → Windows；
* **逐目录 robocopy `/MIR`**（`api` `theme` `build` `tools` `pipeline` `desktop` `config`）：
  早先整仓一次 `/MIR` 会**莫名其妙跳过整棵子树**（实测 `api/web` 882 个文件一个都没拷），
  而症状只是"代码改了、包里没变"；
* `api/web` 再单独同步一次（同一个原因，多一道保险）；
* 密钥与本机配置**不入镜像**：`settings.local.json`（Turso token + 明文密钥）、
  `snapshot.key`、`db/*.enc`；
* 不入镜像的还有：`.git`、`api/.venv`、`vendor/`、`build/dist`、`node_modules`、
  `desktop/dist`、各种缓存。**入镜像**的有一项要留意：`data/quizforge.db`
  —— 自检拿它当样本，验"包里能不能读出真实题库"。

## 四、踩过的坑（都修了，别再踩）

| 症状 | 根因 | 现在怎么防 |
|---|---|---|
| 打完包 `No module named 'app'` | `app` 在 `api/` 下，PyInstaller 从仓库根做静态分析解析不到，**静默**漏收 | `build/package.py` 固定带 `--paths api` |
| 自检跑到一半炸 | Windows 控制台是 **GBK**，输出里的 `✓`（U+2713）编不进去 → `UnicodeEncodeError` | 脚本与启动器都放宽 `errors` |
| 打包报 `PermissionError`，指向 exe | 单文件是"引导进程再起一个真身"，只杀外层会漏下**内层**进程把文件锁住 | 结束时 `taskkill /T`（Windows）/ 进程组（POSIX） |
| 用户的库跑到 `%TEMP%\data` | 打包后 `ROOT` 是解包临时目录，沿用 `<根>/data` 就落在临时目录里 | 打包后数据目录改到 `%USERPROFILE%\quizforge*`，有用例钉住 |
| 内测包拿不到额度 | `ai_beta_config_file` 用 `ROOT` 拼，被打包后指向临时目录 | 改用 `RESOURCE_ROOT`（开发=仓库根，打包=解包目录），有用例钉住 |
| `win-setup` 每次都重装依赖 | PowerShell 往原生命令传参时会**吃掉双引号** → `print("ok")` 变成 `print(ok)` → NameError 被误判成"依赖没装" | 探针改成**不带引号**的 Python，判据用退出码 |
| `winget` 装完却查不到 Python | **PATH 改动不传播进已在运行的进程**（从 WSL 起的 PowerShell 继承的是 WSL 那份环境） | 不查 PATH，直接看安装位置 |
| pip 说"这看起来是个路径" | 忘了 `-r` | 依赖从**镜像**里读（Windows 本地路径），不再走 UNC |
| PyInstaller 在 UNC 上不稳 | 仓库在 WSL 里，Windows 看到的是 `\\wsl.localhost\…` | 工作目录与产物用 `--dist` / `--work` 落到本机盘 |
| 桌面上一直是**旧包** | 目标 exe 正在运行 → 文件被锁 → `Copy-Item` 被静默拒绝，脚本却照样报"完成" | 拷完**核对哈希**，不一致就报错并指出"先把它关掉" |
| 包体积一直 81M | 上次 `--with-pyodide` 构建留下的 76M 没删，日志却写着"无 Pyodide" | `build_web.py` 在不带该开关时**删掉**旧副本 |
| 页面**一片空白**，而接口全绿（对话页、练习中心都是） | 数据目录是空的（题库 0 题）时，`boot.js` 的 `replaceState` 用 `childNodes.length` 判断"已经有内容"，而 `#app-root` 里那句注释 + 换行就算"内容" → 每一屏状态（载入 / 题库为空 / 启动失败）全被挡掉 | 改看**元素**子节点（`children`）；对话页不再被空题库拦下（空库也能开"新对话"），`make dist-verify` 拿空库验这几页 |
| 安装包"没换成"，可桌面上明明是新的 | 在 Linux 上用 `Path()` 取 Windows 路径的文件名 —— `\` 不是分隔符，整条路径被当成一个文件名，哈希核对对着一个不存在的位置比 | 用 `ntpath.basename` |
| 桌面包里**「滤镜」药丸不出现**，开发端正常 | "没有任何会话"的首屏走的是 `renderEmptyThread()`，它只刷工具栏、不补那颗药丸（原先只在 `paintThread()` 里补）；新装的包库里一条会话都没有 | `renderEmptyThread()` 里也补药丸；`make dist-verify` 拿**空库**探一次 chat，断言工具栏里有「滤镜」 |
| 资料页"抓正文 / 模型归类"点了报错（桌面包） | 那两个按钮延迟 `from pipeline import …`，而 `pipeline/` 是仓库根的兄弟目录，没进包；冻结后 `parents[2]` 还指到 `%TEMP%` | 打包时只带 `pipeline/*.py` + `prompts/`（38M 的 `state.sqlite3` 不带）；`REPO_ROOT` 冻结后取 `sys._MEIPASS`；启动检查里试导入一次 |
| 桌面包里主题/开关**不粘**（每次启动回默认） | 外壳每次随机端口 → `localStorage` 的 origin 每次都不同 | 先试固定端口 `8731/8732/8733`，占用了才退回随机 |
| 桌面包里**云同步**一声不响地不动 | `snapshot.key` 只按 `settings_file.REPO_ROOT` 找，冻结后是 `%TEMP%` | 先找数据目录下那份（`~/quizforge/config/snapshot.key`），开发时仍认仓库根 |
| 从 WSL 里 `powershell.exe -Command "...$env:USERPROFILE..."` 得到空路径 | zsh 先把 `$env` 当自己的变量吃掉了（双引号内） | PowerShell 那段用**单引号**包住，或交给脚本里的 `_powershell()` |

## 五、相关命令一览

| 命令 | 用途 |
|---|---|
| `make web` | 构建前端到 `api/web/`（默认**不**拷 76M 的 Pyodide） |
| `make web-full` | 连 Pyodide 一起拷（离线自包含用；产物 81M） |
| `make package` | **当前平台**出包（在 WSL 里会得到 Linux 二进制，只用于验证打包链） |
| `make win-setup` / `make win-sync` | Windows 侧环境（Python + venv + 依赖 + Node）/ 镜像同步 |
| `make dist` | 出包：前端 → 同步 → 后端 exe → 桌面外壳的安装包 → 归位到桌面 |
| `make dist-check` | 桌面上那个包是不是当前代码打的（比对构建戳，不打包） |
| `make dist-verify` | 静默重装 + 逐页截图，验白屏（见二点五） |
| `make user-export` / `make user-import` | 用户数据打包 / 放回（见第七节） |
| `make user-show` | 看一个用户数据包里有什么（只读） |
| `build/package.py manifest` | 从 `vendor/pyodide/` 生成首启下载的哈希清单（产物要提交） |

## 六、包外的东西

**Pyodide（76M）不进包**：第一次打开时取一次进 `<数据目录>\cache\pyodide\`，
逐个校验 sha256（清单 `build/pyodide-manifest.json` 跟着包走，
所以"下到的东西对不对"离线也判断得了）；仓库 `vendor/` 在时直接从它拷过去，**不联网**。
取不到也不影响别的能力：跑 Python 那一项会明确说"暂时不可用"，而不是白屏。

## 七、两类数据包：换机器怎么把数据带过去

源码与产物走上面那套；**数据**走这里。分两类，因为它们俩的生命周期完全不同：

* **题库**（出题机的产物，可选导入）—— `make bank-export` / `make bank-import`
* **用户数据**（自己长出来的，随身带走）—— `make user-export` / `make user-import`

边界不是"约定"，是一份**被用例钉住的声明**：`api/app/datapack.py` 的 `BOUNDARY`
把 `models.py` 里每一张表钉到三类之一，加新表的人必须当场选一边
（`api/tests/test_datapack.py::test_boundary_covers_every_table`）。

| 类别 | 表 | 文件 |
|---|---|---|
| **用户**（进用户包） | `app_settings` `my_questions` `conversations` `conversation_folders` `messages` `attachments` `records` `attempts` `days` `ai_usage` | `data/notes/`（整棵）· `data/library/*.yaml` |
| **题库**（进题库包） | `bank_versions` `topics` `topic_groups` `meta_documents` `questions` `concepts` `concept_edges` `question_concepts` `knowledge_points` `point_sources` `point_edges` `question_points` `materials` `material_slices` `material_figures` `point_candidates` | — |
| **派生**（谁的包都不带） | `slice_embeddings`（本机 **168MB**，占库 82%）· `embed_runs` | `data/library/.text/`（**251MB**，抽出的正文）· `data/cache/`（模型与 Pyodide）· `data/logs/` |

```bash
# 走的时候（这台机器）
make user-export                       # → quizforge-user.qfpack（本机实测 12.2MB / 2.7s）
make user-export ARGS=--with-library-text   # 连资料库抽出的正文一起带（+251MB）
make bank-export                       # → bank.json（题库，可选）

# 到了新机器
git clone … && cd QFStudio
make api-venv && make web              # 环境 + 前端产物
make user-import                       # 库和文件一起放回去（目标已有数据时要 ARGS=--force）
make bank-import                       # 要题目再来这一步
make embed                             # 向量是派生物，按需重建（GPU 约 10 分钟）
make user-show                         # 想看某个包里到底有什么
```

三件容易踩的：

1. **进度是按题目 id 记的。** 用户包把"当时配的是哪份题库"抄在 manifest 里，
   导入时对不上会明确说出来（不会拦），并指向 `make bank-import`。
   对账用两样：`bank_versions.content_hash` 与**直接量出来的内容签名**
   （`id + content_hash`）—— 只看前者会误报，因为它是账，而账会旧。
2. **密钥默认不带出包。** `app_settings.data.ai.apiKey` 在导出时抹空
   （`tools/db_snapshot.py` 为这件事翻过一次车），要带就 `--with-secrets`。
   反过来，导入时包里没带就**保留本机那一把** —— 恢复数据不该把刚填的密钥清掉。
3. **资料库的源文件不在包里。** 元数据（`*.yaml`）在，抽出的正文要 `--with-library-text`；
   源 PDF/HTML 在仓库外的 `reference/`，想看原文得那份目录自己跟着走。
