## 一、形态（一句话）

**对话是前台，题与图是后台。** 学习者在 `chat.html` 里问、被推题、**被现编题**、就地作答；
判分与写回走的仍是刷题页那条路，掌握度 / SM2 / 收藏夹还是同一份记录。

**题有三个来处**，练习与组卷按 `scope=public|mine|all` 区分、卡片上「我的题单」带徽章：

| 来处 | 谁生成 | 落在哪 |
|---|---|---|
| 题库里挑（`push_question`） | 预先出好 | `questions`（权威表） |
| **模型现编**（`create_question`） | 当场 | **不落库**，只挂一张**临时题卡**；按「存进我的题单」才进 `my_questions` |
| 自己攒的 | 用户 / 上面那条存下来的 | `my_questions`（与公共题库**分开的一张表**） |

SQLite 逼出来的六件事（都不是"换个驱动"那么简单，逐条都留了注释）：
① `= ANY(…)` → `IN :x` + `expanding`；② 裸 SQL 读 JSON 列拿到的是**字符串**（PG 给 dict）
→ 统一走 `app.db.as_json`；③ `least/greatest/FILTER (WHERE …)/bool_or/now()` 都是 PG 专有
→ `case` / `COUNT(DISTINCT CASE …)` / `MAX` / `CURRENT_TIMESTAMP`；
④ `BigInteger` 主键在 SQLite 上**不自增**（只认 `INTEGER PRIMARY KEY`）→ `BigAutoId`；
⑤ SQLite **没有时区类型**，读回来是 naive，`timestamp()` 按本地时区算 → `UtcDateTime`；
⑥ `DISTINCT ON` 在 SQLite 上被**静默忽略**（比报错更糟）→ 窗口函数。

  他说得对：加载卡本身没错，错在它有**另外一副样子** —— 那时顶栏与活动栏还没挂上，
  屏幕正中孤零零一张卡片，而前后两页都是设计过的界面，中间夹一屏别的语言。
  原先的判断（"新文档第一帧必须先画点什么，否则会闪一下底色"）只对了一半：
  要画的不是一张卡，而是**这一页自己的骨架**（顶栏 + 活动栏 + 空的内容区）。
  改法两条：
  ① 页面模板里那屏静态骨架屏删掉（`quiz` / `wrongbook` / `chat` / `workbench` 四个；
     图谱页那份**同一天下午晚些也照办了** —— 它长在自己的真实结构里，本来可以先留着，
     但它是一块 `inset: 0` + `background: var(--bg)` 的**不透明遮布**，
     盖着就看不见底下那张画布，所以规矩统一成一条：默认 `hidden`，
     `graph.js` 的 `boot()` 在 `LOADING_AFTER_MS` 之后才露出来、数据一到收回）；
  ② `boot.js` 的 `start()` 一起手先 `mountShellEarly()` 把外壳挂出来，再去取数据；
     "正在载入…"改成**慢启动兜底**：`LOADING_AFTER_MS = 400` 毫秒之后还没数据才出现
     （失败重试那几句也走它，好让人看到"正在再试（第 N 次）"）。
  实测：五个页面的那屏状态**从未出现**（检测窗口 3.2s），外壳首绘 **6–15ms**，
  图谱页画布 **9–22ms** 可见；换页帧序列最瘦 46kB（有内容，改前是 9kB 纯白）；
  十页控制台全清；`make test` 3170 项断言通过。

  各拖 2 秒，1.5 秒时两边都**确实露面**（图谱页 `display: flex`、刷题页那句"正在载入…"），
  数据一到又自动收回 ✓。
  已知代价（可接受）：首帧到数据回来之间内容区是空的 —— 那本来就是原来那张卡
  挡着的一段；跨页那一次被交叉淡出盖住，直接加载时最多也就是一片底色，
  不再是"另一屏界面"。

- **2026-09-30** —— **跨页切换改走浏览器的交叉淡出，并把"窄屏测试"写进纪律。**
  ① 上一版的做法是"点站内链接 → 自己淡出 120ms → 跳转 → 新页淡入"。那 120ms 里
  旧页内容已经透明、新页还没开始画 —— 量出来就是**一段约 120ms 的空舞台**
  （实测"点击 → 新页首帧"：图谱→练习 **249ms**、错题本→练习 **214ms**）。
  用户那句"图谱和错题本到其他几个页面的切换会闪烁，不丝滑"就是它。
  现在改成交给**跨文档 View Transitions**：浏览器把旧页面留成快照、新页面在它上面
  淡入，中间不露空白（同一次测量 249ms → **145ms**，且新页首帧就是实心的）。
  ② 那条 `@view-transition { navigation: auto }` **必须内联在 `theme/shell.html`
  的 `<head>`**：放进外链 `app.css` 会跟"新文档第一次渲染"抢时间，实测同样四条
  跳转只有两条吃到过渡（另两条报 `ViewTransition opt-in disabled`）——**内联之后
  8/8 全中**。这也解释了 2026-09-20 那次"跨文档那条有漏"的记录：当年撤掉的是这个
  竞速，不是机制本身。
  ③ ~~`html:active-view-transition` 下必须关掉 `.view` 的淡入~~ —— **这条是错的，
  当天下午就撤了**（它制造了一个新闪，见 ⑥）。
  ④ `app.css` 里三个视图 / `.study-*` / `.picker-*` / `exam-grid` / `timerbar` 那批
  上一版留下的空壳与死类名一并清掉（`grep` 过一遍，无残留引用）。
  ⑤ **新增一条前端纪律，写进 `AGENTS.md`**：动过 `theme/` 就要做窄屏测试，
  至少过 **1920 / ~1000 / ~390** 三档并**亲眼看过截图**，目标是手机能正常用。
  本次按该纪律把五个界面在 390×844 下过了一遍：无横向溢出（`scrollWidth - clientWidth = 0`）、
  单列堆叠、整页可滚。已知遗留（不属于本次范围）：390 下顶栏那排子导航靠横向滚，
  要不要收成一个"更多"入口是另一件事。
  ⑥ **"画面还是会闪一下"的真因：启动时两套进场动画同时在跑**（用户两次报的都是它）。

  `shell.js` 的 `revealFirstPaint` 记录过用户更早的一句原话 ——"渲染的时候还是会闪
  一下"，当年的应对是给 `#app-root` 加一条从 `opacity: 0` 淡入的动画（`.qf-painted`）。
  问题是**这次交接本来就已经有一套动画**：`app.js` 的 `render()` 第一次进来会走
  `ui.viewSwap`（同文档 View Transition，骨架屏留成快照垫底、内容在它上面淡入）。
  于是两套一起演，而且**错开了**：过渡 250ms 先演完（内容已经清清楚楚），
  `qf-painted` 这时才开始 —— 它淡的是 `#app-root` 自己，而骨架屏已经不在里面了，
  底下露的是**页面底色**。逐帧量 `#app-root` 的透明度（普通加载 quiz.html）：

  ```
  49:100  87:100  137:100  212:100  244:100  334:31  428:96  507:100
                                          ↑ 过渡演完之后整屏掉到 31%
  ```

  这就是"任何页面刷新都会闪一下"，也是"图谱/错题本到其他页面切换会闪"（只有这两个
  方向差别最大：深色画布/长列表撞上白底）。**改法：这次交接只准有一套** ——
  `ui.viewSwap` 起过同文档过渡就由它一个人做完，`qf-painted` 留给没有
  `startViewTransition`（或系统关了动效）的浏览器当兜底。判据是 `ui.usedViewTransition()`。
  改后 `#app-root` 全程 100%；五个方向的换页**最瘦帧从 9kB（纯白）回到 40–46kB（有内容）**。

  同一轮还撤掉了 ③ 那条 `html:active-view-transition .view { animation: none }`：
  过渡一结束伪类就掉，那条被压住的 `qf-page-in` **这时才开始** —— 画面已经画好，
  又被从 `opacity: 0` 淡了一遍（实测到达后 ~428ms `main.view` 的透明度掉到 **0**）。
  会中途启停的动画本来就不该挂在常驻节点上。`.view` 的到达淡入整条撤掉，
  到达交给 View Transitions；同时删掉"拦点击 + 自己淡出"那一整套（链接该不该拦
  本来是浏览器判得更准），JS 只剩两个 `skipTransition` 闸门。

  **四条被实测否掉的思路**（别再走）：
  * **按次申请**（默认不声明 at-rule，跳之前在点击处理器里把 `<style>` 插进
    `<head>`）：浏览器**不认**。它在导航开始时读的是"已算好的样式"，插完同一个
    任务里就跳，读到的还是旧的那份。逼一次 `offsetHeight` / `cssRules` 重算也不行 ——
    实测四次换页一次过渡都没跑。所以那条 at-rule 只能**常驻**在 `shell.html`。
  * 改 `::view-transition-old(root)` 让旧页单向垫底（对称淡出翻白看着不爽）：
    **写 `animation: none` 等于"这层的动画已结束"，整层不画** —— 230–437ms 是一整段
    空屏（实测 5kB 纯底色帧）；改成"停在 `opacity: 1` 的动画"更糟 —— `root` 是**所有**
    过渡共用的选择器，应用自己那套同文档过渡也被套住，旧快照被钉在屏幕上不走，
    整屏糊成一片白（顶栏只剩约 15% 不透明度）。`root` 那一对**别动**。
  * 在**新文档**的 `pagereveal` 里 `skipTransition()`：实测**无效**（无条件调用之后
    过渡照样跑）。规范看着像支持，这台机器的 Chromium 不认账。代码里留着那一小段
    （判据是 `performance.navigation.type === 'reload'`，只在刷新时触发，掐不掉也无害），
    但不指望它。
  * 在**旧文档**的 `pageswap` 里按 `activation.navigationType === 'reload'` 掐：
    只在"浏览器真的建立了过渡"时才触发，而**用户按 F5 那条路径没法在自动化里复现**
    （Playwright 的 `reload()` 是程序化导航，压根不 opt-in）—— 所以这条只能算尽力，
    不能算验过。**验过的是**：同一个地址的点击（同路径，与刷新同一形状）
    `pageswap` 确实触发且跳过成功（`过渡=没跑`）。

  61px（那条进度线也占高），差 3px 就多出一根滚动条；改成 `.view` → `#app-root`
  → `.qz` 一路 `flex: 1 1 auto; min-height: 0` 量出来（中间那层漏了的话，

- **2026-09-23** —— **部署形态定案：宿舍主机当唯一权威，笔记本当客户端。**
  起因是「要不要把材料迁到笔记本 / 干脆租台云服务器」。两条岔路都先被否掉：

  ① **权威库只能有一份。** `db-snapshot` 上头那句写着它是「**唯一进版本库的数据形态**」
  （`Makefile:153`），而 `db-restore` 是**覆盖**语义（`Makefile:169`）—— 两台机器各跑
  一份库、各写各的，等于让两份真相互相冲掉。所以「笔记本也跑一份、靠 git 合并」从根上
  不成立：快照只能用来**交接**（`TUTORIAL.md` 说的「换台机器接着干」），不能**并行**。

  ② **租云服务器 = 把权威库搬走**，不是「多一台机器」：材料要跟着上传（`reference/`
  是仓库外的只读软链，几百 MB 级，见 `.gitignore:30`）、`config/ai.local.json` 的密钥
  要放到租来的机器上、而 `make embed` 用的是**本地** bge-m3 int8 模型
  （`pipeline/embed.py`，45ms/片）—— 便宜的 VPS 这三样一样都不够。

  定案后的形态：**宿舍主机 = 唯一权威**（库 / 材料 / 出题 / `make embed` / API），
  **笔记本 = 浏览器客户端**（`theme/runtime/api.js:5` 的 `apiBase` 本来就可配，不用装东西）。
  **材料不迁**：`api/app/materials.py:69-82` 运行时要读材料正文，所以笔记本上「点开出处
  看原文」会 `MaterialError` —— 这是**功能性降级**，不是崩溃（答题 / 错题本 / 拿路径元
  数据都照常）。一句话：**笔记本是答题机，不是出题机。**

  支撑这个形态的三条硬约束（实测与代码里读出来的，不是推断）：

  | # | 约束 | 出处 | 后果 |
  |---|---|---|---|
  | 1 | **没有 service worker**（全仓 grep 无） | 实测 | 断网**冷启动打不开页面** —— 前端必须从服务器取，`localStorage` 只兜已加载的页面 |
  | 2 | **WSL2 NAT 下绑 `0.0.0.0` 也不挂局域网** | `Makefile:175-177` | 笔记本够不到宿舍主机的 WSL，**除非 Tailscale 装在 WSL 内部** |
  | 3 | `db-restore --force` 是覆盖 | `Makefile:169` | 两台各写一份 = 必然丢数据（见 ①） |

  由此推出一件容易被当成「偏好」的事：**「晚上吵」是阻断项，不是偏好项。**
  宿舍主机一关，笔记本不是「同步不了」，是**连页面都打不开**（约束 1）。所以第一优先级
  是**治噪音**（机械盘换 SSD / 清灰调风扇曲线）—— 一次性投入，比每月租机器便宜，而且
  **绕不过去**：材料、出题、权威库都长在宿舍那台。

  ⚠️ **安全红线**：API **完全没有鉴权**（§五 拆账号时 `deps.py` 只剩 `DbSession`，
  `users` 表连 `password_hash` 一起删了）。能碰到这个端口的人就能读写全部数据 ——
  **只走 Tailscale 私有网，绝不做端口转发、绝不暴露公网**。

  **待办**（回宿舍在主机上做，顺序有讲究）：治噪音 → 把 API 包成 systemd service 并
  `enable`（不开这个，WSL 在最后一个进程退出后会关掉 VM；`/etc/wsl.conf` 的
  `systemd=true` 那台已经有）→ **Tailscale 装进 WSL 内部**（装 Windows 侧到不了 WSL 的
  `0.0.0.0:8100`）→ 笔记本浏览器指 tailnet 地址。

  当时版本号毫无反应，正好就是 ④ 的实例。

  601MB 一次 350ms（查询 367ms 里 350ms 花在这儿，真计算只要 14ms）。
