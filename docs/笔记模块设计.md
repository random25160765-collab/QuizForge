# 笔记模块设计（参考 TriliumNext）

参考实现：`/home/rd/Source/Trilium`（TriliumNext monorepo）。
本文的作用：**把它的笔记管理逻辑逐条对照成我们能用的东西**，避免我凭感觉发挥。
每条都写清楚：它怎么做（带文件:行号）→ 我们怎么落地 → 采纳 / 改造 / 不采纳（附理由）。

## 根本差异：权威在哪

| | Trilium | 我们 |
|---|---|---|
| 权威 | SQLite（`notes` / `branches` / `attributes` / `blobs` / `revisions` 表），内存缓存 Becca/Froca，靠同步协议多端一致 | **Markdown + YAML 文件**（`data/notes/<库>/`），单用户、无同步 |
| 引用键 | 不透明 `noteId`（`[[noteId]]` 渲染成 `#root/<id>`）→ **改名永不断链** | `[[标题]]`（Obsidian 习惯）→ 改名时必须改入链 |
| 树 | `BBranch` 边表，**一条笔记可挂多个父**（克隆） | 文件系统路径，一个文件一个位置 |
| 属性 | `BAttribute`（label / relation 两类），支持继承与模板 | YAML 头 + 正文行内标签 |
| 历史 | `BRevision` 表 + 时间节流 | `.snapshots/` 文件 + 游标 |

**所以：概念照搬，实现一律落在文件上。** 下面凡是依赖 id、内存缓存、同步、blob、加密的，都不搬。

## 一、属性：label 与 relation 是它最有价值的一个抽象

Trilium 把"笔记的元数据"统一成两种东西（`packages/trilium-core/src/becca/entities/battribute.ts:29-40, 97-109`）：

* **label** —— 键值对，界面写 `#name=value`
* **relation** —— 指向另一条笔记，界面写 `~name`（`value` 存目标 id）

两者共用一个表、一个面板、一套补全，于是"打标签""标颜色""声明模板""建立命名关系"是同一种操作。

**我们的落地**：YAML 头就是 label 层，**值写成 `[[...]]` 的键就是 relation 层**：

```yaml
---
title: 数列的极限
tags: [微积分, 极限]        # label（列表 = 多个值）
icon: bx-book               # label（内置属性，见下表）
source: "[[高等数学 上册]]"   # relation（值是双链 → 建立命名关系，进反向链接）
---
```

不新造语法、不引入第二个真源 —— 文件里怎么写，界面就怎么显示。

### 采纳的内置属性词汇表（子集）

它有一张约 300 行的内置属性表（`packages/commons/src/lib/builtin_attributes.ts:77-381`）。我们只取对"单用户 + 文件权威"有意义的那部分：

| 属性 | 作用 | 我们的实现 |
|---|---|---|
| `icon` | 树/标题图标 | 树节点与标题的图标字符（emoji 或短名） |
| `color` | 节点颜色 | 树节点圆点 / 标题左侧细条 |
| `sorted` | 子条目按什么排序（默认 `title`） | **目录级声明**：该目录下条目按 `title` / `created` / `modified` 排 |
| `sortDirection` | `asc` / `desc` | 同上 |
| `sortFoldersFirst` | 目录优先 | 同上 |
| `sortNatural` | 自然序（`1,2,10`） | 同上（默认开） |
| `readOnly` | 只读 | 编辑器禁用输入，仍可复制 |
| `displayMode` | `source` / `split` / `preview` | **每篇默认打开哪种形态**（我们的 编辑 / 分栏 / 阅读） |
| `expanded` | 树里默认展开 | 树初始展开态 |
| `archived` | 归档 | 默认从树里隐去，检索仍能命中 |
| `template` | 这是一篇模板 | 模板目录下的文件 |
| `titleTemplate` | 新建子条目时的标题模板 | 支持 `{date}` `{time}` 占位 |
| `aliases` | **我们加的**（Obsidian 有、Trilium 没有） | 双链解析时一并认，改名时一并改 |

`sorted` 那一组取代了 Trilium 的**手工排序**（`branch.notePosition`，`services/tree.ts:205-223`）—— 文件系统上做手工排序要么写进文件名、要么另开顺序文件，两者都是噪音。**代价说清楚**：我们不能像它那样拖拽排序同级条目，只能"声明排序规则 + 靠改名微调"。

### 不采纳

| 它的做法 | 为什么不搬 |
|---|---|
| `child:` 前缀（父笔记的属性在**创建时物理复制**给子笔记，`services/notes.ts:111-144`） | 落盘复制会漂移（父改了子不跟）。改成**读取时继承**：父目录的 front-matter 声明 `child:icon` 之类，读取时下发，不落盘 |
| `~template` / `~inherit` 属性继承 | 同上机制，先不做；模板只要"新建时套一份内容"就够用 |
| 危险属性白名单（`run=js` 等，`builtin_attributes.ts:100-102`） | 它用它跑脚本。我们不做脚本，白名单只留展示类 |
| relation 必须指向已存在的 note（`battribute.ts:105-107` 抛错） | 我们的双链**允许断链**（写作时先写后建是常态），断链如实标出来、给一键补齐 |

## 三、编辑器：一稿两渲染，它比我的细

它的 Markdown 形态是 `type=code` + `mime=text/x-markdown`（`services/note_types.ts`），走 `SplitEditor`：CodeMirror 源码在左、marked 渲染的预览在右（`widgets/type_widgets/markdown/Markdown.tsx:114-127`）。

三个我该学、而我没做的细节：

1. **三态显示 + 每篇可默认**：`#displayMode` 取 `source` / `split` / `preview`，没设时按是否只读回退（`helpers/split_editor_mode.ts:10-14`）。→ 我们的 `displayMode` 属性映射成 编辑 / 分栏 / 阅读 ✓（我已有三种形态，缺"每篇记住"）
2. **单向滚动同步**：编辑器滚动 → 按顶部源码行 → 把预览滚到带 `data-source-line` 的块（`Markdown.tsx:232-270`）。→ **这是"边写边预览"体感的关键，我没做** ✗
3. **当前行高亮**：光标所在行对应的预览块加背景高亮（`Markdown.tsx:281-317`）。→ 采纳

另外它的自动保存（`apps/client/src/services/spaced_update.ts` + `widgets/react/hooks.tsx:111-206`）：

* 去抖 **1000ms**（Markdown 编辑器传 **750ms**）
* 状态机 `saved / saving / unsaved / error`，渲染成面包屑上的小徽章（`widgets/layout/NoteBadges.tsx:161-205`）
* 失败**指数退避重试**（上限 60s），不丢快照
* `beforeunload` 与切换笔记前强制 flush

→ 我已有去抖保存与状态文字 ✓，**缺退避重试与失败态** ✗。

还有两条值得搬：

* **Markdown 快捷键是"包裹/解包裹"**：`Ctrl+B` 已经在 `**` 里就撤销包裹（`Markdown.tsx:436-511`），比我现在的"只插入"好用
* **拖入图片自动落盘 + 插入 Markdown 语法**（`Markdown.tsx:519-591`）→ 以后做

**不搬**：CKEditor 富文本那一整套、HTML 存储、`api/fonts` 服务端生成样式表、CKEditor 插件体系。

## 四、检索：表达式语言（这个值得整套学）

它有一套表达式检索（`packages/trilium-core/src/services/search/`），并且**全文搜索、快速切换、链接补全用的是同一个引擎**（`services/search.ts:487-520, 777-796`）。

语法要素：`#label` / `#label=value` / `#!label`（取反）、`~relation`、`note.title` / `note.type` / `note.content` 等字段比较、运算符 `= != *= =* *=* %= ~=`、`not` / `and` / `or` / 括号、`orderby` / `limit`。

**我们采纳一个子集**（词法器 + 比较器是纯函数，与存储无关，照搬即可）：

```
#标签                 有某个标签
#标签=值              标签等于某值（我们的标签没有值，写成 tag 即可）
title:极限            标题包含
path:线性代数         路径包含
type:canvas           条目类型
-关键词               排除
A AND B / A OR B / (…) 
orderby title|created|modified [asc|desc]
limit 20
```

纯空格分隔的多词默认 AND，跟它的行为一致。

## 五、修订：策略取它的、能力比我全

它的策略（`services/notes.ts:1053-1071` + `options_init.ts:149-152`）：

* 创建时机：**按时间间隔节流**（默认 600 秒内只留一条），且笔记本身存在时间也要够
* 保留：默认不限条数（`-1`），可被笔记级 `#versioningLimit` 覆盖
* **命名快照**不参与计数（`revisionIgnoreNamedSnapshots=true`）
* `source` 区分 `auto / manual / etapi / llm / restore`
* 界面（`widgets/dialogs/revisions.tsx`）：**能 diff**（`text/code/mermaid` 类型用 `diffWords`）、能恢复、能下载

**我们的取舍**：单用户 + 文件，"每次写都存一份"比节流更精确（也便宜），所以**节流不搬**；但两件事必须补：

1. **命名快照**（手动"存一版"），且不计入游标 —— 对应它的 `manual` + `ignoreNamed`
2. **diff** —— 这正好也是计划里"AI 写入可对比"那条的落点
3. `source` 字段我们已有 `why`（`body/meta/insert/rename/undo/restore`）✓

## 六、明确不做

| 不做的 | 理由 |
|---|---|
| Becca/Froca 内存缓存、`entity_changes`、同步协议 | 为多端增量同步而存在；单用户 + 文件权威下是纯负担 |
| `blobs` 表 + 内容哈希去重 | 文件系统直接存文件 |
| 软删除 + `deleteId` + 延时擦除 | 用 `.trash/` 目录替换 |
| 加密 / 受保护笔记（`isProtected`、protected session） | 它的威胁模型是"服务器上不可读"；我们的目标是 Markdown 永远可读。要加密就整盘加密 |
| `_hidden` / `_options` 等系统子树伪装成笔记 | 应用状态放 `.app/` 配置目录，不混进笔记树 |
| `relationMap` / `mindMap` / `spreadsheet` / `llmChat` 的 JSON 内容模型 | 各自是独立产品，不迁 |
| 手工排序（`notePosition`） | 见 `sorted` 那段的取舍 |
| CKEditor 富文本与 type widget 体系 | 会制造"两份真源"，与 Markdown 权威冲突 |
