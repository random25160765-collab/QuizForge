# 开发经验：2026-09-16 知识图谱化改造

> 写给下一个接手的人（或下一个会话的 agent）。这份是"当天做了什么、踩了哪些坑、
> 下一步做什么"，数值是当天收工时的快照。业务立论见 `THESIS.md`，设计取舍见 `DESIGN.md`。

## 一、今天做完的事（按业务价值排序）

1. **数据库成为唯一权威**。题库、考纲、知识空间、图谱全部以 Postgres 为准；仓库里不再有
   "一题一个文件"。构建与校验改成"先把库物化到**全新临时目录**再读它"。
2. **补上概念层**（图谱的根问题）。原先只有"点"（`knowledge_points`），而点是
   material-scoped 的 —— `tt-metal-circular-buffer` 在 10 份材料里就是 10 个互不相识的点。
   现在：**概念跨材料唯一，点退化为"概念在某材料里的一次出现"**（`concepts` + `points.concept_id`）。
3. **题挂到概念上**（`question_concepts`）。统计口径从"点"切到"概念"，覆盖率不再虚高十倍。
4. **关系从"项目"改回"日志"**。选项辨析 → 易混边、小问复用 → 前置边，由题目产物解析；
   模型判的边降级为"提议"（`derived_by` 区分 `code` / `llm`）。
5. **考点化**：碎片概念按"同切片共现"归到考纲节点（888 / 912 归位，剩 24 个待归类）。
6. **根因诊断接口**（`POST /api/graph/diagnose`）：给一批错题 → 沿前置边回溯 → 给出
   "该补哪个考点、按什么顺序补"。
7. **图谱页接入站点**：`graph.html` 走 `theme/shell.html` 外壳，与刷题页/错题本同级，
   顶栏加入口；数据优先取 `/api/graph`（实时），取不到退回 `graph.json` 快照（离线可用）。
8. **出题目标**（`pipeline/graph_log.py targets`）：`概念目标题量 = 3 + min(3, 跨材料次数-1)`，
   算出缺口约 1269 道，作为出题机的派工依据。

## 三、踩过的坑（**这一段最值得读**）

1. **顶栏接线每个页面各写一份**（刷题页在 `app.js`、错题本在 `wrongbook.js`）。
   新增页面必须自己接一遍，否则症状是：左上角导航整片空白、右上角切主题无反应、设置点不开。
   而且取工具对象要写 **`var QF = window.QF; var ui = QF.ui;`** ——
   写成 `window.ui` 或裸 `ui` 都取不到（两者都实测失败过）。
2. **按主题筛选必须含子孙**。只做精确匹配的话，点一级主题（如 Tenstorrent）永远命中不了
   任何题目（题标签挂在子主题上），表现为"点了没反应"；主题题目数"加起来不对"也是同一个根。
3. **正文里的元信息头**：库里曾把 YAML 头部存进 `raw_markdown`，物化时又拼一个头 →
   双头文件 → 页面把第二个头当正文渲染出来。写入端（`dbstore`）与物化端（`bankfile`）
   都要剥头。已清洗存量 1963 条。
4. **物化目录必须每次全新**。固定目录会跨轮累积：同一道题改过 topic 后以两个文件名共存，
   `check` 报 "id 重复"，产物混进早该消失的旧题（实测 `dist/data.json` 卡在两千多道旧题上）。
5. **`tools/build.py` 不能用 `--incremental`**。增量缓存只看物化目录里的文件，而权威在库：
   库里改了、物化出来同名同路径，缓存就把旧产物认成新的。
6. **工具不能假设题目文件在仓库内**。`path.relative_to(ROOT)` 在物化到 `/tmp` 后会抛错，
   把整个校验带崩；需要"questions/ 之后的那一段"做稳定相对路径。
7. **批量删除（>500 个文件）会被安全闸门拦下**。所以 Makefile 的 `check` / `test` / `build`
   里**不要**塞 `rm -rf`；清理物化临时目录交给 Python 的 `shutil.rmtree`（那是流水线自己的中间产物）。
