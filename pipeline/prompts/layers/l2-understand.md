# 出理解层题目

## 这一层在考什么

**能做出预测和判断，而不是能复述。**

识记层的题可以靠关键词匹配蒙对；理解层的题必须**懂机制才能答对**。
所以本层的核心手法是：**换一个说法、换一个情形，看还能不能答对**。

四种最有区分度的形态：

1. **换个说法**——不用材料原句，用等价但不同措辞的表述，问它对不对
2. **给新情形**——给一个定义没直接覆盖的同类情形，问它属于哪一类 / 会怎样
3. **给反例**——问「什么情况下 X 会失效 / 不成立」
4. **审读**（agent 时代的主力形态）——给**一整段**多句的解释或一段代码（可以是 agent 生成的、
   读起来很顺的那种），问：它对不对、哪一句错、错在哪、后果是什么。
   与前三者的区别在于「材料」是一整段而不是一句话，所以它能测出「每个词都认得、整段读下来却
   发不现问题」这种失败模式——这正是与 agent 协作时最常见的翻车方式。

   **审读题的边界**：考点仍然只有**一个机制**，只是承载它的材料长。
   如果题目要求「用 A 的结论推出 B」，而不是「在同一段材料里认出 A 被用错了」，
   那就是跨知识点综合，归 `l4-transfer`。

## 判定标准：这题是不是真的在理解层

| 问自己 | 是 | 否 |
|---|---|---|
| 答对是否**必须**懂机制？能否靠题干与选项的字面匹配蒙对？ | 继续 | 字面能匹配 → 降级成识记题，改用 `l1-memorize` |
| 题干是否直接抄了材料原句？ | 那是阅读题，改写 | 继续 |
| 是否有一个选项对应**真实的常见误解**？ | 继续 | 四个选项都在瞎编，重写 |
| 是否需要多步计算才能答？ | 那是应用层 → 用 `l3-apply` | 继续 |
| 是否要用 A 的结论推出 B（而非在同一段材料里认出 A 被用错）？ | 那是迁移层 → 用 `l4-transfer` | 继续 |

**滑坡警告**：把定义里的词换成同义词就当成理解题——那只提高了阅读难度。
真正的理解题要改的是**提问的角度**，不是措辞。

## 题型选择

| 场景 | 题型 |
|---|---|
| 判断某个说法对错 / 给出新情形问归类 | `single` |
| 多条机制表述同时判定 | `multi` |
| 「为什么」「解释机制」「举一个反例」 | `short` |

## 构造规则

1. **题干用等价改写，不用原文**。原文可以在 `## 解析` 里引用，帮助学习者回到材料。
2. `single` 的选项应当是**互不相同的机制解释**，不是同一句话的几种措辞。
   至少一个选项来自真实的常见误解（例如「把必要当成充分」「过度外推一个定理的适用范围」）。
3. 干扰项要在 `### 选项辨析` 里点明**它对应哪种思维错误**——这比「B 错」有用得多。
4. `short` 必须有 `## 参考答案`，`## 评分要点` 每条要写成**可判定命中**的短句
   （「提到 X」，而不是「回答得好」）。
5. **禁止**需要多步计算（应用层）；**禁止**跨知识点综合（迁移层）。
6. 如果这道题的答案在材料里找不到依据，**不要出**。

## 输出骨架

字段细节与长模板见 `references/format.md`（见文末绝对路径）。

```markdown
---
id: <topic>-<四位编号>
type: single              # 或 multi / short
topic: <meta/topics.yaml 里的 key>
chapter: <章节名>
tags: [<概念>, ...]
layer: 理解                # 本 skill 固定填「理解」
wing: 基础                 # 默认「基础」；要串联同单元内多个知识点时填「综合」
source: "<材料文件>: <小节标题>"
---

<题干：改写过的表述，或一个新情形>

## 选项
- A. ...
- B. ...

## 答案
A

## 解析
### 选项辨析
- **B 错**：<错在哪 + 对应哪种思维错误 + 什么人会选它>

### 机制
<机制层面的解释。可以引用材料原文或指向具体小节。>
```

`short` 把 `## 选项` / `## 答案` / `### 选项辨析` 换成 `## 参考答案` + `## 评分要点`。

## 写完之后

1. 自查上面「判定标准」表的五问，尤其第一问。
2. 把 `### 选项辨析` 里的每一条读一遍——如果某个干扰项说不出「什么人会选它」，就换掉。
3. 校验：

```bash
cd "$(git rev-parse --show-toplevel)"  # 仓库根（克隆在哪都行）
python3 tools/check.py questions/<subject>/<file>.md
python3 tools/build.py
```

4. 汇报：新增文件、`check.py` 最终输出、**哪几处事实依据薄弱需要人工复核**。
