# 出识记层题目

## 这一层在考什么

**准确回忆，而且不混淆。**

关键是后半句。只问「X 的定义是什么」，考的是背诵，几乎人人都能答对，区分度为零。
识记层的价值在于**把容易混的两个东西分开**：

- 相近术语（`left_inverse` vs `right_inverse`）
- 相近数值（`size` vs `cosize`）
- 相近枚举（surjective onto cosize vs onto `[0, size)`）

所以本层的默认形态不是「默写」，而是**二选一的辨析**。

## 判定标准：这题是不是真的在识记层

| 问自己 | 是 | 否 |
|---|---|---|
| 不看选项，能否说出唯一答案？ | 继续 | 题干缺条件，先修 |
| 答对是否只需要回忆，不需要推理？ | 是识记题 | 混进了理解层 → 用 `quizforge-l2-understand` |
| 干扰项是否来自「真实会混淆的另一个东西」？ | 继续 | 干扰项是凑数的，重写 |

**滑坡警告**：「请说明 X 与 Y 的区别」看起来像辨析，但它要求组织语言、解释机制，
那是**理解层**。识记层的辨析必须能在二选一的形态里完成。

## 题型选择

| 场景 | 题型 |
|---|---|
| 两个相近概念二选一 | `single` |
| 多处表述同时判定（≥2 个正确、≥1 个错误） | `multi` |
| 写术语名 / 写数值 / 写出枚举集合 | `blank` |

不要用 `single` 装一个需要解释的问题；不要用 `multi` 把多个互不相关的知识点塞进一题。

## 构造规则

1. **题干必须给出足以定出唯一答案的条件**。缺条件 → 审核必退。
2. **干扰项来自真实的混淆源**：把材料里并列出现的术语、相邻的数值、容易记反的枚举拿来做干扰项。
   每个错误选项都要能说出「什么人会选它」。
3. **禁止否定式与双重否定**（「下列哪个不正确」）——那是在加阅读理解难度，不是在考识记。
4. **只出「有后果的词」**。判据不是它在材料里出现几次，而是**用错了会不会出问题**。
   像 `TT_METAL_SLOW_DISPATCH_MODE`、`cb_reserve_back` 这类只出现过一次、但方向弄反就会出错的词，
   恰恰是最该考的；反过来，一个出现十次、写不写都不影响结果的名字，不值得占题位。
   完全装饰性的细节（版本号、示例里的人名）仍然不要出。
5. `blank` 的答案要**短且唯一**（一个术语 / 一个数 / 一个集合）。
   同一含义的多种写法用 `|` 或 `~` 正则覆盖，例如 `cosize|~^co[- ]?size$`。

## 输出骨架

字段细节与长模板见 `references/format.md`（见文末绝对路径）。

```markdown
---
id: <topic>-<四位编号>
type: single              # 或 multi / blank
topic: <meta/topics.yaml 里的 key>
chapter: <章节名>
tags: [<术语>, ...]
layer: 识记                # 本 skill 固定填「识记」
wing: 基础                 # 默认「基础」；一题内同时辨析多个知识点时填「综合」
source: "<材料文件>: <小节标题>"   # 人类可读线索，不做机器核对
---

<题干>

## 选项
- A. ...
- B. ...

## 答案
A

## 解析
### 选项辨析
- **B 错**：<错在哪 + 什么人会选它>
- **C 错**：...

### 为什么这样设置
<为什么正确答案对，以及这个知识点在体系里的位置>
```

- `### 选项辨析`（写在 `## 解析` 内部）只对 `single` / `multi` 写，
  **每个错误选项都必须出现**——这是审核的判定项之一。
  解析器只认 `##` 那一层的小节名，`###` 属于正文，所以可以自由使用。
- `blank` 用 `## 答案` 逐行列出（每行一个空），不需要 `### 选项辨析`。

## 写完之后

1. 自查上面「判定标准」表的三问。
2. **逐条核对事实**——包括材料本身可能写错的情况，不要盲信原文。
3. 校验：

```bash
cd "$(git rev-parse --show-toplevel)"  # 仓库根（克隆在哪都行）
python3 tools/check.py questions/<subject>/<file>.md
python3 tools/build.py
```

4. 汇报：新增文件、`check.py` 最终输出、**哪几处事实依据薄弱需要人工复核**。
