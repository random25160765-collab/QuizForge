# 出迁移层题目

## 这一层在考什么

**换掉外衣之后，还认不认得里面的原理。**

迁移层和应用层的区别不在于「更难」，而在于**解法不能直接套用**。
判定只有一条：**只背了应用层解题步骤的人，能不能蒙对。**

因为这一步风险最高（容易变成「应用题换个数」或「开放到无法判分」），
本 skill 强制要求标注**迁移锚点**与**迁移手法**，供审核核对。

## 三种变式手法（必须用其中一种，并写明用的是哪种）

| 手法 | 做法 | 例子 |
|---|---|---|
| **换情境** | 同一个原理换到不同载体上 | 把 GEMM 的分块复用原理放到别的计算上 |
| **换问法** | 从「求 X」变成「为什么不能 X」/「什么条件下 X 失效」/「反过来设计」 | 不问「访存量是多少」，改问「要满足某上界，tile 至少多大」 |
| **跨知识点综合** | 把 A 的结论作为 B 的输入条件（A、B 都必须在考纲内） | 先用分块算算术强度，再用 roofline 判断瓶颈类型 |

## 判定标准：这题是不是真的在迁移层

| 问自己 | 是 | 否 |
|---|---|---|
| 把应用层的解法步骤背下来，能否直接套用？ | 那是应用题，回 `quizforge-l3-apply` | 继续 |
| 是否需要**重新组合已知原理**才能解？ | 继续 | 只是套公式 → 回应用层 |
| 情境是否真的换了（不是只换数值）？ | 继续 | 只换数值 → 假迁移，重做 |
| 是否超纲（需要材料之外的领域知识）？ | 降级或补材料 | 继续 |
| 是否开放到无法判分？ | 收窄设问或补评分要点 | 继续 |
| 是否写明了**迁移锚点**（迁移的是哪个原理）？ | 继续 | 补上，否则无法审核 |

**滑坡警告**：最典型的假迁移是「同一道应用题，把 $64$ 换成 $128$」。
真正的迁移一定改变了**问题的结构**——换情境、换问向、或增加一个需要串起来的知识点。

## 题型选择

| 场景 | 题型 |
|---|---|
| 需要多步、且各步可独立判分 | `problem`（首选） |
| 要求说清一个判断或设计取舍 | `short` |

迁移层**不用** `single` / `multi`：二选一挡不住「套用记忆」的路径。

## 构造规则

1. **必须写明迁移锚点**：在 `tags` 里带上被迁移的原知识点，并在 `## 解析` 开头一句写出
   「本题把 <原理> 迁移到 <新情境>，相对于 <原知识点/原题> 的变式是 <换情境/换问法/跨点综合>」。
   这一句是审核的判定依据，不是装饰。
2. **情境细节可以虚构**（人名、设备、业务背景），但**底层原理必须与材料一致**。
   虚构的部分不得引入材料的原理之外的新规则。
3. **每一步都要能独立判分**；`problem` 的每个小问写 `#### 评分要点`。
4. 需要跨知识点时，**所有涉及的知识点都必须在 `meta/topics.yaml` 里存在**。
   缺就先补考纲，不要挂在一个不存在的 key 上。
5. **开放题也要有评分要点**：把「可接受的方向」写成若干条可判定命中的要点，
   不要出现「言之成理即可」这种无法判分的表述。
6. **相对原题的改动要说得出来**。如果写不出「它和应用题的区别在哪」，那就是应用题。

## 输出骨架

字段细节与长模板见 `references/format.md`（见文末绝对路径）。

```markdown
---
id: <topic>-<四位编号>
type: problem             # 或 short
topic: <meta/topics.yaml 里的 key>
chapter: <章节名>
tags: [<被迁移的原知识点>, <新情境>, ...]
layer: 迁移                # 本 skill 固定填「迁移」
wing: 创新                 # 默认「创新」；偏实务的换情境题可填「应用」
source: "<材料文件>: <小节标题>"
---

**题干** <新情境的背景与全部约束>

**说明** <本题共 N 问；如涉及多个知识点，在此点明>

## 小问

### 第一部分 · 第 1 问｜<小问标题>

<要求>

#### 参考答案
<完整解答>

#### 评分要点
- <可判定命中的要点>
```

`short` 把 `## 小问` 结构换成 `## 参考答案` + `## 评分要点`。

## 写完之后

1. 自查上面「判定标准」表的六问，尤其第 1 问（能不能直接套用）。
2. 把迁移锚点那一句读一遍——**它是这道题存在的理由**。
3. 校验：

```bash
cd "$(git rev-parse --show-toplevel)"  # 仓库根（克隆在哪都行）
python3 tools/check.py questions/<subject>/<file>.md
python3 tools/build.py
```

4. 汇报：新增文件、`check.py` 最终输出、以及
   **本题的迁移手法与迁移锚点**——迁移层与创新翼的题**必须点名请人过目**，
   因为「是不是真迁移」只有人读得出来。
