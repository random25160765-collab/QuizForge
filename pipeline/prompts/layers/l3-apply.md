# 出应用层题目

## 这一层在考什么

**按已知规程，独立、正确、完整地算出确定结果。**

「已知规程」是关键：解题路径是材料里给过的方法，不需要临场发明。
所以判定应用层题好坏的标准只有一条：**答案能不能从题干唯一算出来**。

## 判定标准：这题是不是真的在应用层

| 问自己 | 是 | 否 |
|---|---|---|
| 我是否**从头到尾自己算过一遍**？ | 继续 | 没算过就不许出 |
| 答案能否**由题干条件唯一算出**？ | 继续 | 缺条件 → 补条件或换题 |
| 所有需要的常量是否都在题干里给全？ | 继续 | 依赖题外常量 → 不成题 |
| 数值是否太整，以致能靠背「典型值」答对？ | 换参数或要求给表达式 | 继续 |
| 解题路径是否**标准规程**？ | 继续 | 需要发明新方法 → 那是迁移层，改用 `quizforge-l4-transfer` |
| 是否必须综合多个知识点？ | 那是迁移层 → 用 `quizforge-l4-transfer` | 继续 |

**滑坡警告**：只把数值换掉就当成一道「新题」——那还是同一道题，考的是记忆而非应用。
要么换参数结构，要么换问法（从「求结果」换成「求表达式」或「判定能否满足某界」）。

## 题型选择

| 场景 | 题型 |
|---|---|
| 结果是数 / 表达式 / 一行代码 | `blank` |
| 需要多步推导，且中间结论值得单独给分 | `problem` |

结果只是「一个数」时优先 `blank`（作答快、可精确判分）；
一旦有 2 个以上可独立判分的中间结论，就用 `problem` 拆成小问。

## 构造规则

1. **先自己解一遍**，把关键中间步骤写进 `## 解析` 与 `## 评分要点`。
   这既是答案也是 rubric——没算过就别出。
2. **参数必须自洽**：单位统一、量级合理、需要整除的地方能整除。
   数值题要在解析里点明单位与数量级。
3. **避开「背典型值」**：要么用非典型的参数组合，要么要求同时给出符号表达式。
4. **给出可判定的中间量**。`problem` 的每个小问要能独立判分；
   需要复用前问结论时，在题干里写明「可引用第 N 问的结果」。
5. **明确作答精度**（如「保留 3 位有效数字」「写成 $a/b$ 的形式」），
   否则 `blank` 的答案无法唯一匹配。
6. **禁止**依赖题干未给出的常量；**禁止**需要材料之外的领域知识。
7. `blank` 的多个可接受写法用 `|` 或 `~` 正则覆盖（如 `32|~^32(\.0+)?$`）。

## 输出骨架

字段细节与长模板见 `references/format.md`（见文末绝对路径）。

```markdown
---
id: <topic>-<四位编号>
type: blank               # 或 problem
topic: <meta/topics.yaml 里的 key>
chapter: <章节名>
tags: [<方法>, ...]
layer: 应用                # 本 skill 固定填「应用」
wing: 应用                 # 默认「应用」；在一题内串联多个知识点时填「综合」
source: "<材料文件>: <小节标题>"
---

<题干：背景 + 全部已知条件 + 要求解的量 + 精度要求>

## 答案
<每行一个空；多种写法用 | 或 ~ 正则>
```

`problem` 的结构：

```markdown
## 小问

### 第一部分 · 第 1 问｜<小问标题>

<该问的条件与要求>

#### 参考答案
<完整解答，含中间步骤与公式>

#### 评分要点
- 关键中间量一
- 关键中间量二

### 第一部分 · 第 2 问｜<小问标题>
……
```

## 写完之后

1. **按自己写的参考答案反向验算一次**：把结果代回题干条件，看是否自洽。
2. 检查每个 `blank` 的答案是否真的唯一——有没有第二种合理写法会被判错？
3. 校验：

```bash
cd "$(git rev-parse --show-toplevel)"  # 仓库根（克隆在哪都行）
python3 tools/check.py questions/<subject>/<file>.md
python3 tools/build.py
```

4. 汇报：新增文件、`check.py` 最终输出、**哪几处数值或结论需要人工复核**。
